# Antfly SQL Grammar Remaining Slices

This is the tracking document for the SQL grammar migration. It lists only
remaining migration work and should stay checklist-shaped. Keep design
rationale, architecture decisions, ownership boundaries, and implementation
invariants in `GRAMMAR.md`. Completed history that is deducible from code,
tests, fixtures, or git history should stay out of both docs.

Completed read-plan and DML cutover slices are intentionally omitted from the
active checklist.

Feature work is listed first, followed by parser cutover, diagnostics, and
evidence/performance hardening. Check a slice only when the implementation,
diagnostics, and verification evidence are all in place.

Prefer generated AST dispatch and typed plan persistence over expanding local
token-layout interpreters. Tokenized payload hardening is acceptable for
correctness bugs in still-live compatibility paths, but it does not by itself
complete a generated-owned slice. Do not keep broadening tokenized payload
support where the remaining work is to retain, validate, lower, or persist a
generated AST/typed-plan shape.

When a remaining slice admits a new grammar terminal or promotes generated
syntax that production tokenization cannot already represent, keep the
production lexer path in the same patch: `TokenKind`/`TokenKeyword` in
`token.zig`, lexer recognition in `lexer.zig`, generated-token bridge mapping,
and focused lexer/parser fixtures. Prefer contextual keyword bridge handling for
generated-only words that must still be valid identifiers outside the new
grammar context. Lowering-only changes for terminals that production
tokenization already recognizes do not need lexer churn.

- [ ] Legacy fallback removal and production parser cutover
  - [ ] Keep the fallback inventory current and executable. Current production inventory:
    - DDL public boundary: `parseLogicalDdlPlanAlloc` dispatches retained generated ASTs through `planGeneratedLogicalDdlAstAlloc`; `ddlPlanParsedSqlAlloc` now requires retained generated metadata and rejects no-generated-AST DDL admission. Generated-supported catalog families lower through generated AST dispatch plus typed command-tail validators, and generated unsupported catalog-boundary lowering now uses retained subject tokens or deterministic unsupported diagnostics instead of a broad whole-statement DDL parser.
    - Runtime DDL residuals: remaining DDL cutover work is subject/raw SQL payload ownership for trigger/function/procedure/view/materialized-view and similar subject-bearing families, plus public-boundary corruption/parity evidence for each admitted subject family as it becomes generated-owned. Do not reintroduce whole-statement DDL token parser admission.
    - Read boundary: `ReadPlanLoweringContext.lowerParsed` lowers retained generated read ASTs before classifier fallback. Generated set-operation reads now route through typed set-operation lowering or the explicit generated-owned select-set query optimizer for admitted same-source set-operation folds, instead of generic query-plan fallback. Source-bound native graph `MATCH ... WITH GRAPH ... ON ... START ...` no longer reparses synthetic SQL and now lowers generated unsupported-AST graph metadata directly to typed `antfly.graph_match` table-function plans for the currently admitted projection/filter/order/pagination subset.
    - DML boundary: generated DML lowering is mostly retained-AST owned; remaining raw token probes/reparses are assignment/source/target helpers and document-write classifier paths that must be audited against retained generated expression/list metadata before deletion.
    - Persisted child payloads: generated DDL scalar-subquery defaults lower retained child read ASTs directly before schema persistence and fail closed if retained child metadata is absent. Runtime schema derivation now normalizes old persisted scalar-subquery default `{"kind":"tokenized_sql"}` query payloads to structured query JSON; row execution and `scalarSubqueryDefaultPlanFromQueryJsonAlloc` reject direct tokenized query payloads.
    - Subject/raw SQL reparses: trigger/function/procedure/view/materialized-view and other subject-bearing DDL still retain subject token ranges or parsed subject SQL for compatibility; remove only after each subject family has generated AST validation/lowering or deterministic unsupported diagnostics.
  - [ ] Complete native graph public cutover beyond the direct lowerer now used by `ReadPlanLoweringContext.lowerNativeGraphParsed`: graduate the public SQL/API graph rows that still intentionally report `graph_query_plan`, keep retained-AST corruption coverage aligned with every admitted graph payload, and broaden typed graph planning beyond the current source-bound projection/filter/order/pagination subset only when row shape and runtime parity are proven.
  - [ ] Retire the schema-ingress-only legacy tokenized scalar-subquery default normalizer after a catalog/storage migration marker proves persisted schemas can no longer contain `{"kind":"tokenized_sql"}` scalar-subquery defaults. Until then it is limited to schema derivation normalization and is not reachable from row execution or public scalar query-plan parsing.
  - [ ] For each DDL subject/payload family still routed through raw SQL reparsing or subject-token compatibility parsing, promote it to one of:
    - retained generated AST lowering,
    - deterministic generated unsupported diagnostics,
    - or documented non-generated legacy-only admission.
  - [ ] Add tokenized public-boundary retained-AST corruption tests before deleting each generated-covered fallback. Corruption coverage must prove stale/malformed generated metadata fails closed before legacy parsing can accept the SQL.
  - [ ] Add or update SQL/API parity rows, required native/unsupported manifests, and focused runtime tests for each fallback removal so public behavior is either native-equivalent or deterministically unsupported.
  - [ ] Run fixture promote/check, relevant unsupported-reason checks, focused retained-AST corruption tests, and full SQL/API parity before marking a fallback family removed.
