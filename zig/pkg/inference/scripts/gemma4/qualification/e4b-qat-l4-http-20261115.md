# Gemma 4 E4B QAT: L4 HTTP qualification, 2026-11-15

This report covers the native production inference HTTP server on one NVIDIA L4 (SM89, 23,034 MiB), Linux x86-64, four vCPUs, CUDA 13.2, driver 580.159.03 and Zig 0.17.0. The focused `bench-server` build calls the same `runServer` implementation as `antfly inference run`. The reference is llama.cpp b12387, built with CUDA 12.8. Other GPUs and longer request envelopes are not performance-qualified by this campaign.

## Artifacts and measurement

Both engines read the same `google/gemma-4-E4B-it-qat-q4_0-gguf` artifacts at revision `4b4a2c1d584be7264f87aac328a1bc739ce81b6c`:

- Decoder `gemma-4-E4B_q4_0-it.gguf`: SHA256 `676c35070db6dbe52f93e9c864ee0fba4eddea94b9c875d9cb10daff453fbaee`.
- Projector `gemma-4-E4B-it-mmproj.gguf`: SHA256 `7498a37cb619e55f2fcf87eb931f56e99389ed6d432e4c5c66110694c0d65578`.

Requests use greedy decoding, disabled thinking, F16 K/V, disabled prompt caching and streaming HTTP. Performance requests ignore EOS and must complete exactly 256/128/64/64/64 output tokens. Latency includes request submission through the final SSE event, usage and `[DONE]`. TTFT uses the first visible content/reasoning delta. Decode throughput counts the remaining output tokens through stream completion. One engine process runs at a time; GPU compute-process checks precede every arm. Three fresh lifecycles alternate arm order. There is one unmeasured first call, then two short-text warmups and one warmup for each other cell.

The reference explicitly uses `--image-min-tokens 256 --image-max-tokens 280` to match the native prepared-image grids. The three images produce 278, 284 and 273 total prompt tokens in both engines. With only the 280-token maximum, llama.cpp leaves the smaller receipt at 252 tokens while Antfly uses 284; that earlier unmatched campaign is excluded from superiority claims. The text and audio request settings are unchanged by this image-only comparison setting.

The 35 requests per lifecycle are 12 short sentences, 12 pages, six 1,500-word passages, three images and two audio clips: 105 measured calls per engine. Text sampling follows the supplied termite-circus recipe and seed 20261103 over a retained Gutenberg pg1228 snapshot (SHA256 `362142cb7c6f90850477520cfe2a62fe423ae92ea8eb6d9cd8b30ddb39de60b9`). The unavailable release corpus/media snapshots prevent claiming an exact reproduction of the release page. Repository letter/receipt/shipping PNGs and English/Spanish WAVs are explicit media substitutes. The portable checked-in fixture has the same canonical requests/media hashes as the measured local fixture (`aeb341d8c325dc54d056d38113b91427a6ea9dd0214d350ff0ce92e2f81bcd1b`).

Memory is the maximum simultaneous sum of process-tree Linux PSS and per-process NVML usage, polled every 0.2 seconds, including startup and warmups. A suite's peak is not a per-cell peak. VRAM is reported separately. PSS excludes unmapped reclaimable OS file-cache pages; these figures do not measure all physical RAM in the host.

## Implementation and scope

- Consume Q4_0 GGUF blocks directly in the BF16 prefill kernel, avoiding a persistent repacked copy (about 2.22 GB on this artifact). Multi-row cuBLAS prefill uses bounded temporary dequantization. Original GGUF bytes remain unchanged.
- Retain completed compact projector uploads once per store identity with their own backend-weight leases. Bound cache bytes/entries; keep borrowed allocations admitted through their last reader. Exact-size temporary reuse and bounded idle eviction avoid retaining unsuitable buffers across request shapes.
- Keep a bounded 1,024-entry cuBLASLt descriptor cache for the qualified E4B/L4 model, with an explicit capacity override and no descriptor eviction. Diverse prompt lengths retain their shape/alignment-specific plans instead of repeatedly discovering algorithms after a smaller cache fills. Separate diagnostic runs record the 256-entry control and 1,024-entry candidate counters; these diagnostic timings are excluded from the paired results above.
- Run the final row through Gemma's 18 shared-KV suffix layers for text and prepared media. Preserve the full 24 donor layers, original modality-masked PLE rows and absolute positions. Decline masked, packed, query-capture and incompatible contexts.
- Use the qualified vision attention and fused F32 norm/spatial-RoPE kernels. Optional symbols and artifact-body checks retain compatible fallbacks, including portable PTX whose SM80-only entry body is empty.
- For fresh serialized greedy requests with exact F16 paged K/V, reserve the 16-aligned prompt-plus-output capacity before the first write. Automatic replay is limited to at most 4,096 total tokens and 512 requested output tokens. Compaction, observers, fit probes, prefixes, checkpoints, speculation, compiled execution and interleaved owners retain existing contracts. Explicit replay/capacity settings override the automatic policy; automatic requests outside the envelope retain existing behavior.
- Retain the original F16 PLE projection in its native storage on the qualified L4 path. The singleton projection preserves F32 arithmetic exactly; multi-row projection uses F16 activation operands with F32 accumulation. F32 source tensors retain their original path. The fused F32 audio frontend is qualified separately.
- Chunk proven mapped uploads and release clean source PTEs after completed reads, reducing process startup footprint. Warm metadata/compatibility lookups remain bound to artifact publication and backend policy.

Defaults are scoped to the measured dense E4B/L4 geometry and required kernel capabilities. Explicit rollback controls remain available: `ANTFLY_INFERENCE_CUDA_GEMMA4_ADAPTIVE_REPLAY_CAPACITY=0`, `ANTFLY_INFERENCE_CUDA_DECODE_GRAPH_REPLAY=off`, `ANTFLY_INFERENCE_CUDA_PLE_MODEL_PROJ_F16=0`, `ANTFLY_INFERENCE_CUDA_GEMMA4_AUDIO_LOGMEL_FUSED=0`, `ANTFLY_INFERENCE_CUDA_E4B_PREPARED_SHARED_KV_PREFILL=0`, and the existing per-kernel/cache controls. RMS/BF16, Q8 activation and generated-head controls remain opt-in; the exact subset measured by this report is listed above. BF16 PLE projection remains off.

In the same-binary cache controls, recorded request boundaries reached 256/256 cached plans and 660 uncached plan publications with the smaller cache, versus 275/1024 cached plans and 0 uncached publications with the larger cache. All 35 native output texts and prompt counts match between controls. These observations use `ANTFLY_INFERENCE_CUDA_GEMMA4_PLAN_CACHE_STATS=1`; the headline paired campaign leaves that diagnostic off.

## Correctness and limits

All **116 focused CUDA/ownership/policy/graph/planner tests pass**, with zero skips on the L4. All 16 HTTP stream and campaign-validator tests pass, including error/truncation handling, exact completion caps, matched prompt counts, complete pairing, deterministic native text, and valid simultaneous memory peaks.

The direct raw-Q4 kernel qualification preserved the previous BF16 kernel's outputs bitwise across 324 standalone cases (81 packaged cases also checked); Compute Sanitizer reported zero errors. The vision register-attention kernel differs from the previous FP16 attention kernel by at most 2.38418579e-7 across 14 isolated cases; its production header passed Compute Sanitizer. The F32 vision norm/RoPE fusion has an independent F64 oracle. Native F16 PLE storage is byte-exact, with bit-identical singleton outputs versus the F32-widened checkpoint values and bounded multi-row error.

The raw-Q4 qualification additionally checks up to 64 outputs spanning each matrix against an independent CPU reference (GGUF nibble dequantization, BF16 operand rounding, F64 accumulation). Across 324 standalone and 81 packaged cases there are zero CPU mismatches. The explicit per-output absolute tolerance is `1e-5 * sum(abs(BF16(a) * BF16(weight))) + 1e-6`; maximum observed error/bound is 0.0733187. This sampled CPU check complements the full-output bitwise comparison with the previous CUDA kernel.

Full-model inference is not claimed bit-identical across changed execution routes. Same-binary media pruning preserved all five first-token argmaxes and the tested full OCR/ASR outputs. Common top-64 logit differences reached 0.316535, with at least 62/64 overlapping IDs. These diagnostics disable pending-token emission solely to expose prefill logits and are excluded from performance results.

Three structured long-text contracts pass for both engines. Letter/receipt/shipping OCR and the English ASR ground truth pass; the Spanish ASR fixture has the recorded pre-existing wording mismatch and is checked for regressions rather than relabeled as correct. The larger scratch quota, when used, has separate long-text semantic checks.

antfly: expanded JSON suite strict 0/12, correct JSON content after separately stripping one Markdown fence 11/12. These pre-existing formatting/content failures are not counted as passes; there are no new failures against the frozen baseline.

llama: expanded JSON suite strict 0/12, correct JSON content after separately stripping one Markdown fence 10/12. These pre-existing formatting/content failures are not counted as passes; there are no new failures against the frozen baseline.

A mapped-host PLE-table probe saved about 2.31 GB of device allocation and passed bitwise gather/graph tests, but it is not implemented in the serving runtime and is not credited in these results. VRAM superiority must be assessed independently from the combined footprint.

## Post-review replay correction

Explicit `ANTFLY_INFERENCE_CUDA_DECODE_GRAPH_REPLAY=auto` now disables persistent replay, capture scalars and graph capture for requests outside the qualified 512-output / 4,096-total-token envelope, retaining eager execution as K/V grows. The request boundary clears that decision so a following eligible request can replay. Only `required` mode returns `CudaGraphReplayRequired` for that rejection. Exact-limit acceptance, both limit overruns, zero-length and overflow cases are covered by the new CUDA regression test.

The updated source passes 117 CUDA tests with zero skips (ordinary non-watch build/run, exit status 0), plus all 16 HTTP stream/validator tests. The rebuilt production server completes a 513-token output, a prompt exceeding 4,096 total tokens and a subsequent normal request under both explicit `auto` and unset replay mode. Eager fallback includes scalar/replay preparation because the process-wide automatic setting can otherwise capture a graph against a growing K/V allocation. These cold-start functional probes are excluded from the performance table. Their request counts, binary/source hashes and validation details are retained under `post_review_replay_validation` in the accompanying JSON; the original V13 benchmark hashes and all 210 timing samples remain unchanged.

## Reproduction

Build the focused CUDA production inference server from the repository root, using Zig 0.17.0 and the checked-in SM89 artifact. Keep both caches and output inside the worktree:

```sh
ZIG_GLOBAL_CACHE_DIR="$PWD/.zig-cache/global" \
LD_LIBRARY_PATH="/usr/local/cuda/lib64${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}" \
  zig build --build-file zig/pkg/inference/build.zig bench-server \
  -Doptimize=fast -Dstrip=true -Dcuda=true -Dmetal=false -Dcuda-artifacts=sm89 \
  --cache-dir "$PWD/.zig-cache/inference" --prefix "$PWD/zig-out" -j1 \
  -Dbench-server-compile-memory-mb=12000
```

The resulting `zig-out/bin/antfly-inference-bench-server` uses the production inference server. The paired runner also accepts the ordinary CLI binary named `antfly`. Install `psutil` and `nvidia-ml-py` in the runner's Python environment, then run:

```sh
python3 zig/pkg/inference/scripts/gemma4/benchmark_cuda_http_pair.py \
  --antfly zig-out/bin/antfly-inference-bench-server \
  --llama /path/to/llama-server \
  --model /models/google/gemma-4-E4B-it-qat-q4_0-gguf/gemma-4-E4B_q4_0-it.gguf \
  --mmproj /models/google/gemma-4-E4B-it-qat-q4_0-gguf/gemma-4-E4B-it-mmproj.gguf \
  --fixtures zig/pkg/inference/scripts/gemma4/fixtures/e4b_cuda_http_v1.json \
  --llama-image-min-tokens 256 \
  --antfly-env ANTFLY_INFERENCE_CUDA_RMS_Q8_1_MIRROR=1 \
  --antfly-env ANTFLY_INFERENCE_CUDA_GENERATED_Q6_K_Q8_1_LM_HEAD_ARGMAX=1 \
  --antfly-scratch-budget-mb 4096 \
  --lifecycles 3 --repeats 1 --cold-call \
  --output /path/to/fresh-results
```

The runner checks pinned model checksums, retains responses/raw timings, records fixture/media/binary/harness hashes and commands, samples memory, and refuses a stale results directory. `build_cuda_http_fixtures.py` can regenerate the corpus from the retained Darwin snapshot; the checked-in fixture avoids depending on future changes at the upstream URL.

Validate complete pairing, equal prompt counts, exact completion caps, deterministic native text and valid memory samples before interpreting the medians:

```sh
python3 zig/pkg/inference/scripts/gemma4/summarize_cuda_http_pair.py /path/to/fresh-results
```

This writes `validated-summary.json` with latency, TTFT, decode rate, lifecycle medians and separate combined-footprint/VRAM comparisons. A valid summary can still report a performance loss; validation does not relabel a slower result as a win.
