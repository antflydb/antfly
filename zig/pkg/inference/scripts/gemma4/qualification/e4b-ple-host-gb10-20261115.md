# E4B host PLE: GB10 validation, 2026-11-15

This validates optional mapped-host placement of Gemma 4 E4B's Q6_K per-layer token-embedding table. The test host is glowworm: NVIDIA GB10 (SM12.1), unified memory, driver 580.178.04, Linux aarch64 and Zig 0.17.0. The production HTTP server uses the checked-in fatbin. No new CUDA kernels or regenerated GPU artifacts are needed.

**Scope:** another user's GPU evaluation was active throughout the diagnostic campaign. These timings cannot qualify uncontended latency or L4/PCIe performance. Host placement stays off by default. The table bytes and quantization are unchanged; this moves residency between memory domains rather than establishing lower total physical RAM.

This is historical evidence for the source hashes recorded in the JSON. Later
review fixes harden retirement ownership, placement-aware admission, contention
monitoring and output-contract validation. The recorded HTTP campaign is not a
measurement of those revisions; discrete-GPU qualification remains deferred.

## Correctness

- All 45 focused CUDA tests pass, zero skips. The Metal-enabled ownership/admission build passes all 44 selected tests.
- Compute Sanitizer memcheck reports zero errors and zero leaked bytes/allocations for the mapped gather and captured fused decode test.
- Device and host storage produce bit-identical prefill gathers, device-token gathers and captured fused RMS/embedding decode outputs. The graph replays changing device token IDs; original upload bytes can be released or changed independently.
- Full HTTP text, reasoning and complete usage dictionaries match exactly across all 60 measured requests, including repeated fresh processes. This preserves the control's outputs; it is not an independent semantic-quality evaluation.

The same binary alternates device/host, host/device, device/host across three fresh paired lifecycles. Each arm has one warmup per workload, ten measured requests, then one unmeasured request to flush final allocation observations. Two calls per workload are selected evenly from the frozen portable fixture: short text `[0,11]`, pages `[0,11]`, long text `[0,5]`, images `[0,2]`, audio `[0,1]`. Output caps remain 256/128/64/64/64. That is 30 measured requests per placement, six per workload. Model, projector, fixture, media, server and harness hashes, source hashes, output contracts, raw timing samples and lifecycle medians are retained in the [JSON evidence](e4b-ple-host-gb10-20261115.json).

Source hashes identify the measured files. Subsequent changes expand Apache license headers in three new files and format the Python harness through the required pre-commit hook. Zig executable bodies and the Python AST are unchanged; final-file and body/AST hashes are recorded in the JSON evidence.

## Allocation result

| Managed allocation | Device placement | Host placement | Difference |
|---|---:|---:|---:|
| Resident CUDA weights | 7,413,380,264 | 5,101,270,184 | -2,312,110,080 bytes |
| Peak CUDA allocations across the suite | 9,641,201,356 | 7,329,091,276 | -2,312,110,080 bytes |
| Retained host PLE table | 0 | 2,312,110,080 | +2,312,110,080 bytes |

The load lease reserves the source mapping and extra pinned copy together, then retains host storage for the loaded model's lifetime. CUDA readers finish before storage retires. The mapped descriptor cannot enter the GPU temporary-buffer pool. Admission failures retain the existing fail-closed contract.

The counters above track allocations owned by Antfly, excluding CUDA/vendor-internal allocations. Separate process-tree PSS and per-process NVML maxima are retained, but **GB10 has unified memory**: they must not be summed into a physical-RAM or dedicated-VRAM claim. L4's previous 7.508 GB suite VRAM figure is not remeasured here. Subtracting this table suggests about 5.196 GB only if other peak allocations stay unchanged; that is an unqualified projection, not a result.

## Reproduction

From the repository worktree, keep caches and the output prefix inside that worktree:

```sh
ZIG_GLOBAL_CACHE_DIR="$PWD/.zig-cache/global" zig build \
  --build-file zig/pkg/inference/build.zig bench-server \
  -Doptimize=fast -Dstrip=true -Dcuda=true -Dmetal=false -Dcuda-artifacts=fatbin \
  --cache-dir "$PWD/.zig-cache/inference" --prefix "$PWD/zig-out" -j1 \
  -Dbench-server-compile-memory-mb=16000

ZIG_GLOBAL_CACHE_DIR="$PWD/.zig-cache/global" zig build \
  --build-file zig/pkg/inference/build.zig test-gemma4-ple-host \
  -Doptimize=fast -Dcuda=true -Dmetal=false -Dcuda-artifacts=fatbin \
  --cache-dir "$PWD/.zig-cache/inference" --prefix "$PWD/zig-out" -j1

python3 zig/pkg/inference/scripts/gemma4/benchmark_cuda_ple_host.py \
  --server zig-out/bin/antfly-inference-bench-server \
  --model "$HOME/.antfly/inference/models/google/gemma-4-E4B-it-qat-q4_0-gguf/gemma-4-E4B_q4_0-it.gguf" \
  --fixtures zig/pkg/inference/scripts/gemma4/fixtures/e4b_cuda_http_v1.json \
  --output .benchmark-results/ple-host/fresh-run \
  --lifecycles 3 --calls-per-cell 2 --allow-cotenant
```

The runner requires `psutil` and `nvidia-ml-py`. Omit `--allow-cotenant` on an idle GPU and omit `--calls-per-cell` for the full fixture. It refuses an existing output directory, requires exact output parity, validates sampler operation and confirms that requested host/device placement was observed. The early aborted full-size contended campaign is retained locally and excluded from these results.

For a dedicated E4B process, `ANTFLY_INFERENCE_CUDA_GEMMA4_PLE_HOST=1` enables host placement; omit it or set it to `0` for device placement. `ANTFLY_INFERENCE_CUDA_GEMMA4_MEMORY_STATS=1` enables allocation observations. The benchmark uses a 12,288 MiB host admission ceiling to cover the additional pinned table, and a 4,096 MiB scratch ceiling; these are quotas, not eager allocations.
