# Workload scheduling entry-point inventory

This inventory records the current execution owner at the public boundary. It
does not certify an operator for suspension, demotion, or protected-lane use.
Those require an operator-specific continuation bound and state-transition test
under [the scheduling design](WORKLOAD_SCHEDULING.md).

| Entry point / work | Current execution owner | Cancellation and retained-state boundary | Scheduling status |
| --- | --- | --- | --- |
| Query, lookup, scan, and relational status | [Public route policy](pkg/antfly/src/api/request_admission_policy.zig) and [query/scan/lookup handlers](pkg/antfly/src/api/httpx_handler.zig) acquire a query lease. [Query dispatch](pkg/antfly/src/api/workload_dispatch.zig) retains the transport request. | The route holds execution admission through result construction or stream completion; response bytes can remain charged through drain. A general query is not automatically resumable. | General lane by default; only audited bounded existence probes use protected execution. |
| Batch writes and transaction commit | The same [public policy](pkg/antfly/src/api/request_admission_policy.zig) gives [batch and commit handlers](pkg/antfly/src/api/httpx_handler.zig) write admission. [Distributed commit](pkg/antfly/src/api/distributed_txn.zig) and [session recovery](pkg/antfly/src/api/transactions.zig) retain durable post-decision obligations. | Client cancellation is allowed before the durable decision. After it, recovery owns the obligation, independent of response lifetime. | Foreground write lease; no mid-commit suspension claim. |
| Synchronous artifact-range reprocess | [Public handler](pkg/antfly/src/api/httpx_handler.zig) now acquires the write lease before calling [range reprocessing](pkg/antfly/src/api/table_writes.zig), which may visit multiple groups. | The request owns execution for the pass; response bytes can remain charged through drain. Its separate job-start/status routes create or inspect durable job state and do not hold a foreground pass lease. | Coarse write execution; no yield/demotion claim. |
| Graph metric action and one-shot repair | [Graph action](pkg/antfly/src/api/httpx_handler.zig) and [one-shot repair](pkg/antfly/src/api/httpx_handler.zig) remain `.none` in [public policy](pkg/antfly/src/api/request_admission_policy.zig). | Their synchronous work and helper lifetimes have not been measured against a bounded execution owner. | Audit before assigning a protected/general scheduling lane. |
| Dense rerank and native helpers | [Workload scheduler](pkg/antfly/src/common/workload_scheduler.zig) owns admitted driver/helper jobs; [implementation audit](WORKLOAD_SCHEDULING_IMPLEMENTATION.md) records exact workspaces and one verified I/O suspension boundary. | `yieldState` retains accounted continuation bytes and `demoteAtYield` transfers at a verified boundary. Other native operations retain coarse ownership. | Integrated on audited paths only. |
| Vector, text, graph traversal, and aggregation | The enclosing query request remains admitted via [public query routes](pkg/antfly/src/api/httpx_handler.zig); storage and graph operators hold their own scratch/snapshot resources. | Cooperative checkpoints and maximum non-yielding regions are not comprehensively inventoried. | General execution; no protected-lane or demotion guarantee. |
| Background index, TTL, enrichment, and repair | [Backend runtime](pkg/antfly/src/storage/background_runtime.zig) provides finite worker/control lanes and the [maintenance scheduler](pkg/antfly/src/common/maintenance_scheduler.zig) owns scheduled jobs. | Job state persists or retries according to each owner; background submission pressure cannot borrow foreground query capacity. | Separate background/control owners; sustained mixed-load fairness remains unqualified. |
| Backup, restore, and durable maintenance jobs | [Backup](pkg/antfly/src/api/backups.zig), [restore](pkg/antfly/src/api/restore_jobs.zig), and [repair](pkg/antfly/src/api/http_server.zig) keep their job-specific state beyond the initiating response. | Start/status/control routes are not execution leases for the entire job. Each long-running worker needs its own resource and progress proof. | Entry points classified as control; job-wide byte/count floors remain to be measured. |

The public policy is exhaustive over generated routes in
[the OpenAPI route contract](pkg/antfly/src/api/openapi_contract.zig). This
checks coverage of names, while the execution ownership above still requires
review when a route changes from job control to synchronous data work.
