# Owning-thread inference checkpoints

The synchronous borrowed-provider host phase installs a TLS checkpoint scope alongside its native CPU scope. InferenceExecutionControl.check invokes that checkpoint only on the owning OS worker. Copied controls on watchdog/parallel threads have an empty TLS slot. Nested scopes restore in stack order, and the scope is removed before returning the parent grant. Errors continue through provider response cleanup and original parent return checks.

The focused antfly-inference-parent-phase-test gate passes all eight tests on native macOS (15 steps) and pinned Nix/glibc aarch64-linux-gnu (12 steps), with zero skips, failures or leaks and exit 0. The host test traverses the installed scope, and the worker-isolation regression spawns an actual second OS thread, checks nested failure propagation, and verifies cleanup removes the callback. Both result files pin the two changed source hashes; complete logs are retained. The first GNU attempt failed before compiler startup because the read-only worktree lacked a cache mountpoint; that failure is retained and the unchanged source passed after creating the ignored mountpoint.

This qualifies synchronous checkpoint propagation, not model numerical correctness or whole-request fairness. Subprocess callbacks cannot use process-local parent pointers; delegated child work still needs its physical scheduling/wait contract. Other provider/HTTP admission, resource waits, foreign backend teams, production archive qualification of these newer bytes, overload behavior and automatic defaults remain outstanding.
