# Recording the README quickstart

Run [quickstart.tape](../../quickstart.tape) from the repository root with VHS,
FFmpeg, zsh, and a current `antfly` binary on PATH (or `./antfly`). The tape shows
table creation, loading 10,000 documents, a SQL count, the 10% embedding-coverage
threshold, full-text search, semantic search, locally reranked hybrid search, and
a cited answer generated by OpenAI `gpt-4.1-mini` from a local article.

This recording uses a hosted generator and incurs OpenAI usage. Embeddings,
reranking, and retrieval run locally. The [quickstart guide](../../docs/guides/quickstart.mdx)
continues to document the all-local option and image search; this short recording
covers the stages above.

## Prepare an isolated server

Use a fresh data directory for each take. The tape creates `wikipedia` and exits
on a failed Antfly command; it does not drop an existing table. Do not point the
recording at a database with data you want to keep.

```sh
mkdir -p .recordings
curl --fail --location --output wiki-articles.jsonl \
  https://cdn.antfly.io/datasets/wiki-articles-10k-v001.json
antfly inference pull hf:google/embeddinggemma-2:bf16-safetensors-bundle-v1
antfly inference pull hf:mixedbread-ai/mxbai-rerank-base-v1 --tasks rerank
```

Start standalone in a separate terminal, outside the recording. Configure
`OPENAI_API_KEY` in that server's environment through your normal credential
setup, or pass `--secret-store-path /absolute/path/to/secrets.json` with an
`openai.api_key` entry. See [secrets management](../../docs/reference/secrets.md).
Never paste a key into the tape or its JSON configuration.

```sh
antfly standalone --port 18089 \
  --data-dir "$PWD/.recordings/quickstart-server-take1"
```

The checked-in [generator.json](generator.json) contains only a secret reference.
The server resolves it; the recording terminal does not need the API key. Model
execution needs sufficient available memory while background indexing runs.
Download models before capture and wait for the server's `/healthz` endpoint to
return success. Use a new data-directory name when rerunning.

## Capture and review

From the repository root, in the recording terminal:

```sh
export ANTFLY_URL=http://127.0.0.1:18089
vhs validate quickstart.tape
vhs quickstart.tape > .recordings/quickstart-vhs.log 2>&1
```

Outputs stay under ignored `.recordings/`: `quickstart.mp4`, a terminal text
transcript, and `quickstart-commands.log`. The command log records the first two
arguments and exit status, not request bodies or credentials. Each Antfly command
must exit zero. Start a new command log for each take, or retain separate take
directories before rerunning. Preserve raw captures before editing.

The tape clears between chapters and hides idle waits after briefly showing the
command. Its visible comments disclose shortened waits. `source-covered=10%`
means partial coverage, not complete indexing; keep the partial-index warnings in
the export. Check the count is 10,000, all search results are readable, and the
answer ends with a complete sentence and a matching source title. Results and
answer wording can change between takes as indexing continues.

## Edit and export

The published 2026-10-23 capture used two chapters joined into a 67.76-second
raw MP4. [published-20261023-edit.json](published-20261023-edit.json) preserves its
exact timeline: the first chapter plays at 1.2x, followed by the answer at its
original speed and a 0.36-second final hold. The export is silent, 1200×640,
60 seconds, and 600 GIF frames. These offsets describe that archived capture;
inspect a fresh recording and choose new offsets before reusing the recipe.
The single tape now records both chapters together.

With that original joined capture saved as `.recordings/quickstart-full-raw.mp4`,
the plan can also be rendered using stock FFmpeg:

```sh
ffmpeg -n -i .recordings/quickstart-full-raw.mp4 -filter_complex \
  '[0:v]trim=start=0:end=47.52,setpts=(PTS-STARTPTS)/1.2[a];[0:v]trim=start=47.72:end=67.76,setpts=PTS-STARTPTS,tpad=stop_mode=clone:stop_duration=0.36[b];[a][b]concat=n=2:v=1:a=0,fps=25[v]' \
  -map '[v]' -an -c:v libx264 -pix_fmt yuv420p \
  .recordings/quickstart-full-human-60s.mp4
```

Export a reviewed MP4 as a GIF with a compact palette:

```sh
ffmpeg -n -i .recordings/quickstart-full-human-60s.mp4 -filter_complex \
  '[0:v]fps=10,scale=1200:-1:flags=lanczos,split[a][b];[a]palettegen=stats_mode=diff:max_colors=128[p];[b][p]paletteuse=dither=bayer:bayer_scale=3:diff_mode=rectangle' \
  -loop 0 .recordings/quickstart.gif
ffprobe -v error -show_entries format=duration,size:stream=width,height,nb_frames \
  -of json .recordings/quickstart.gif
ffmpeg -v error -i .recordings/quickstart.gif -f null -
```

Decode checks complement visual review: inspect every chapter, the index-wait
disclosure, partial-coverage warnings, and the full final answer before publishing.
Stop the dedicated server after recording and remove any temporary credential
file. Keep originals and new exports under separate names.

## Published artifact

The README uses `https://cdn.antfly.io/quickstart.gif`; updating that object does
not require committing a binary to Git. The immutable version of this take is
[quickstart-full-human-20261023-071e0be2.gif](https://cdn.antfly.io/quickstart-full-human-20261023-071e0be2.gif).
Its SHA-256 is `071e0be22c9fcf518c1d673b4a2df5d4f8289ac1c7316237e676084dce8f046e`
and its size is 3,240,304 bytes.

Publication is separate from recording: upload a new versioned object first,
verify public bytes, check the canonical object still has the expected previous
ETag, then replace it. Keep the previous version for rollback. Use
`Content-Type: image/gif`, immutable caching for versioned keys, and a short
cache lifetime for the canonical key.
