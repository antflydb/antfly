## Install Antfly

One command on macOS or Linux:

```bash
curl -fsSL https://releases.antfly.io/antfly/latest/install.sh | sh
```

Or pin a specific version:

```bash
curl -fsSL https://releases.antfly.io/antfly/latest/install.sh | sh -s -- {ANTFLY_VERSION}
```

On macOS you can also use Homebrew:

```bash
brew install antflydb/taps/antfly
```

Either way you get the `antfly` binary — the native Zig runtime with Antfly
Inference built in. From here, the [Quickstart](/docs/guides/quickstart) takes
you to a running engine and your first query.

  <TabsContent value="brew">
```bash
brew install antflydb/taps/antfly
```

or tap homebrew-taps and install separately:

```bash
brew tap antflydb/taps
brew trust --formula antflydb/taps/antfly
brew install antfly
```

The trust step is required for short-name installs from non-official taps.

CLI commands are available directly as `antfly <command>` (e.g., `antfly query`, `antfly table create`).

To run Antfly as a local service:

```bash
brew services start antfly
```

  <TabsContent value="docker">
Run a single node with Docker Compose, with the public API on port 8080 and data persisted in a named volume:

```yaml
services:
  antfly:
    image: ghcr.io/antflydb/antfly:latest
    command: ["standalone", "--host", "0.0.0.0"]
    ports:
      - "8080:8080" # Public API
    volumes:
      - antfly-data:/antflydb
    restart: always

volumes:
  antfly-data:
```

Antfly Inference runs inside the same process, so no separate model server is needed. Pull models with `docker exec <container> antfly inference pull <model>`.

## Upgrading

A new release may migrate table files in place when opening an existing data
directory, and that migration can be one-way: an older binary may subsequently
fail to open the directory with `InvalidTableFile`.

Create and verify a portable backup before upgrading, and restore that backup
into a fresh data directory if you need to roll back. Do not rely on swapping
the binary while reusing a directory that a newer release has opened.
