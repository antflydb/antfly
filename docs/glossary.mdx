## Antfly Concepts

### Antfly Inference

The model runtime built into Antfly. It runs embedding, chunking, reranking, extraction, transcription, and generation models from GGUF, safetensors, and [ONNX](#onnx-open-neural-network-exchange) artifacts on native CPU, Metal, and CUDA backends, plus experimental PJRT/XLA and WASM/WebGPU backends. Standalone serves it in-process under `/ai/v1`; `antfly inference run` runs it as a separate process that a database reaches through `inference.api_url`.

See: [Antfly Inference](/docs/guides/inference) | [Local Model Compatibility](/docs/guides/supported-models) | [Inference Components and Providers](/docs/guides/inference-providers)

### CDC & Foreign Sources

Two ways to work with an external PostgreSQL table. **CDC** (`replication_sources` on a table) uses logical replication to stream inserts, updates, and deletes into canonical Antfly storage. **Foreign sources** (`foreign_sources` on a query) read or join the external table at request time without ingesting it, and support only filters, field selection, and paging.

See: [Mirror a PostgreSQL Table](/docs/guides/cdc-replication) | [CDC design](https://github.com/antflydb/antfly/blob/main/zig/CDC.md)

### Document Extraction

The `document_extraction` asset producer downloads a document URL during enrichment and persists derived units such as PDF pages and chunks. Native text is extracted with no model. Scanned pages and images are read when the config's `ocr` block names a reader, such as [LightOnOCR-3](/docs/guides/models/lightonocr3); without one they report `ocr_not_configured`. Audio is transcribed when a `transcription` block names a `transcriber`. This durable ingestion path is distinct from [template](#templates) helpers such as `remoteMedia`, which prepare media for inference without persisting page artifacts.

### Enrichments, Artifacts & Asset Producers

An **enrichment** is a named producer that generates and maintains **artifacts**, durable outputs attached to a document and exposed under `_artifacts`. Enrichment kinds are `chunk`, `asset`, and `embedding`. Summaries, extraction, OCR, transcription, and decisions are all `asset` artifacts made by an **asset producer** (`copy`, `generator`, `extractor`, `decision`, `reader`, `transcriber`, or [`document_extraction`](#document-extraction)), and indexes can consume artifact streams as sources.

See: [Artifact Indexes](/docs/guides/artifact-indexes) | [Artifacts design](https://github.com/antflydb/antfly/blob/main/zig/ARTIFACTS.md) | [Enrichments design](https://github.com/antflydb/antfly/blob/main/zig/ENRICHMENTS.md)

### Lake Tables

*In progress.* Lake query mode serves Parquet datasets and Iceberg tables that stay in your object storage through the same relational row plans, pushing predicates and projections down into file reads instead of copying every row into Antfly. It ships with the SQL work tracked in [#145](https://github.com/antflydb/antfly/pull/145).

See: [Lake design](https://github.com/antflydb/antfly/blob/main/zig/LAKES.md) | [Remote table serving](https://github.com/antflydb/antfly/blob/main/zig/REMOTE_TABLE_SERVING.md)

### Relational Tables

A second table profile on the same engine. The schema is required and closed, and every declared scalar property becomes a typed column, so predicates, sorts, and aggregations run columnar. The `relational` index type adds composite ordered keys on these tables.

See: [Relational mode design](https://github.com/antflydb/antfly/blob/main/zig/RELATIONAL.md)

### remotePDF (deprecated)

`remotePDF` is a deprecated Handlebars helper retained for compatibility. Use `remoteMedia` for template-time multimodal inference, or `document_extraction` when PDF pages and chunks should be durable and reprocessable.

### SQL & pgwire

*In progress.* SQL is lowered to Antfly's native typed plans, and an optional PostgreSQL wire-protocol (pgwire) listener lets `psql`-compatible clients connect. Tracked in [#145](https://github.com/antflydb/antfly/pull/145).

See: [SQL design](https://github.com/antflydb/antfly/blob/main/docs/design/sql/extraction.md) | [pgwire transport](https://github.com/antflydb/antfly/blob/main/zig/pkg/antfly/src/pgwire/README.md)

### sync_level

How long a batch write waits before returning: `propose` (Raft proposal accepted, the default), `write` (durably applied to the local store), `full_text` (full-text index WAL written), `enrichments` (enrichments precomputed before commit; a synchronous producer failure rejects the write), or `full_index` (all index writes complete).

### Templates

Handlebars templates turn a document into the text or media that a model sees, for embedders, rerankers, and enrichments. Built-in helpers include `scrubHtml`, `eq`, `media`, `remoteMedia` (download a URL into a media part, such as an image), and `remoteText` (fetch a URL's text), with downloads guarded by host allowlists, private-IP blocking, and size limits.

See: [Multimodal Embeddings](/docs/guides/multimodal) | [Handlebars](https://handlebarsjs.com/guide/)

### Transforms

In-place document updates with MongoDB-style operators (`$set`, `$setOnInsert`, `$unset`, `$inc`, `$push`, `$pull`, `$addToSet`, `$min`, `$max`), sent in the `transforms` array of a batch. They apply atomically at the storage layer, which avoids read-modify-write races, but results are not validated against the table schema.

## AI & Machine Learning

### Agent

An autonomous AI system that can plan, reason, and take actions to accomplish goals. Antfly has three native agents: the Retrieval Agent (`POST /agents/retrieval`) for retrieval, tool selection, and generation; the Query Builder Agent (`POST /agents/query-builder`) for turning natural language into executable Antfly queries; and the Research Agent (`POST /agents/research`, with durable runs under `/agents/research/jobs`) for cited long-form reports. Agents may use [tools](#tool-use) and operate over multiple bounded steps, and [A2A](#a2a-agent2agent) exposes them to other agents.

See: [Write a Cited Research Report](/docs/guides/deep-research) | [ReAct: Synergizing Reasoning and Acting in Language Models](https://arxiv.org/abs/2210.03629)

### Chunking

The process of splitting large documents into smaller pieces for indexing and retrieval, so each piece fits an [embedding](#embeddings) model's input. In Antfly a chunker is configured on an index or enrichment, not at query time. The default `fixed` model splits by token count (and by fixed windows for audio and images), and a source shared by several indexes is chunked at most once per write.

See: [Chunking Strategies for LLM Applications](https://www.pinecone.io/learn/chunking-strategies/)

### Embeddings

Dense vector representations of text, images, or other data that capture semantic meaning. Similar concepts have similar embeddings (close in vector space). Managed index creation supports Antfly Inference, Ollama, OpenAI, OpenRouter, Cohere, Gemini, Vertex AI, and AWS Bedrock. Used by [AKNN](#aknn-approximate-k-nearest-neighbors) indexes for similarity search. See also [Sparse Vectors & SPLADE](#sparse-vectors--splade).

See: [Word2Vec](https://arxiv.org/abs/1301.3781) | [Sentence-BERT](https://arxiv.org/abs/1908.10084) | [MTEB Leaderboard](https://huggingface.co/spaces/mteb/leaderboard)

### Evals

Short for "evaluations" - systematic testing of AI system quality. Evals measure metrics like retrieval accuracy, answer relevance, and latency. They're essential for comparing different [models](#model-mlai), prompts, or configurations and ensuring system quality over time.

See: [RAGAS: Evaluation framework for RAG](https://docs.ragas.io/) | [OpenAI Evals](https://github.com/openai/evals)

### Generators

Models that produce text, images, or other content. In [RAG](#rag-retrieval-augmented-generation) pipelines, generators (typically LLMs) take retrieved context and user queries to produce final answers. Antfly's Retrieval Agent (`POST /agents/retrieval`) streams generated answers via Server-Sent Events.

### Genkit

An open-source framework for building AI-powered applications, with abstractions for LLMs, [embeddings](#embeddings), and retrieval. Antfly ships a Genkit (Go) plugin, `github.com/antflydb/antfly/go/pkg/genkit/antfly`, that exposes an Antfly table and index as a Genkit retriever.

See: [Antfly Genkit plugin](https://github.com/antflydb/antfly/tree/main/go/pkg/genkit/antfly) | [Genkit](https://github.com/firebase/genkit)

### Inference Components & Providers

Antfly names each kind of inference a component: embedder, reranker, chunker, reader (OCR), transcriber, speech synthesizer, generator, extractor, decider, and web search. A provider runs a component: the built-in Antfly runtime or a connected service such as OpenAI, Gemini, Bedrock, or Cloudflare. Each configured component is a named entry with a `provider` and a `model`.

See: [Inference Components and Providers](/docs/guides/inference-providers)

### Model (ML/AI)

A trained machine learning system that performs specific tasks. In Antfly's context, this includes embedding models (convert data to vectors), [reranker](#rerankers) models (re-score search results), vision models (process images), and [generator](#generators) models (produce text). Models run locally on [Antfly Inference](#antfly-inference) from [GGUF, safetensors](#gguf--safetensors), or [ONNX](#onnx-open-neural-network-exchange) artifacts on its native backends, or remotely through an API provider.

See: [Hugging Face Model Hub](https://huggingface.co/models)

### Multimodal

Systems that work with multiple data types - text, images, audio, video. Antfly supports multimodal indexing and search, allowing you to search across different content types. Multimodal [embeddings](#embeddings) (like CLIP or Gemini) create unified vector representations across modalities.

See: [CLIP: Learning Transferable Visual Models](https://arxiv.org/abs/2103.00020) | [Antfly Multimodal Guide](/docs/guides/multimodal)

### Multiturn Chat

Conversational interactions spanning multiple exchanges where context is preserved across turns. Unlike single queries, multiturn chat requires managing conversation history, resolving references ("it", "that"), and maintaining coherent dialogue state.

### NER (Named Entity Recognition)

The task of identifying and classifying named entities (people, organizations, locations, dates, etc.) in text. NER can enhance search by extracting structured information from unstructured documents, enabling [faceted search](#facetting) and knowledge graph construction.

See: [spaCy NER](https://spacy.io/usage/linguistic-features#named-entities) | [Stanford NER](https://nlp.stanford.edu/software/CRF-NER.html)

### Pruners

A query processor that drops low-quality results by score. In Antfly the pruner runs once on the merged results, after fusion and any reranking and before offset/limit paging. Its options are `min_score_ratio`, `max_score_gap_percent`, `min_absolute_score`, `std_dev_threshold`, and `require_multi_index`. See also [Rerankers](#rerankers).

### RAG (Retrieval-Augmented Generation)

A technique that combines search/retrieval with generative AI. Instead of relying solely on an LLM's training data, RAG retrieves relevant documents and provides them as context for generation. This produces more accurate, grounded, and up-to-date responses. In Antfly, RAG is the Retrieval Agent at `POST /agents/retrieval`, which streams its answer over Server-Sent Events.

See: [Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks](https://arxiv.org/abs/2005.11401) | [RAG in the Quickstart](/docs/guides/quickstart#rag-retrieval-augmented-generation)

### Rerankers

Models that re-score and reorder search results for improved relevance. Unlike initial retrieval (which must be fast), rerankers can use more sophisticated cross-attention between query and document. Antfly supports rerankers as query processors that refine results from [hybrid search](#hybrid-search), with `antfly`, `cohere`, and `vertex` providers. See also [Late Interaction](#late-interaction-colbert--maxsim).

See: [Cross-Encoders](https://www.sbert.net/examples/applications/cross-encoder/README.html)

### Tokenizers

Components that split text into tokens (subwords, words, or characters) for processing by ML [models](#model-mlai). Different models use different tokenization schemes (BPE, WordPiece, SentencePiece). Tokenizer choice affects vocabulary size, handling of rare words, and multilingual support.

See: [Hugging Face Tokenizers](https://huggingface.co/docs/tokenizers/) | [BPE Paper](https://arxiv.org/abs/1508.07909)

### Tool Use

The ability of AI [agents](#agent) to invoke external functions or APIs to accomplish tasks. Tools extend an agent's capabilities beyond text generation - searching databases, executing code, calling APIs, or interacting with external systems.

See: [Toolformer](https://arxiv.org/abs/2302.04761) | [Anthropic Tool Use](https://docs.anthropic.com/en/docs/build-with-claude/tool-use)

## Search & Indexing

### Agentic Search

Search that goes beyond simple query-response patterns. An agentic search system can reformulate queries, explore multiple search paths, synthesize information from different sources, and iteratively refine results to better answer user intent. See also [Semantic Search](#semantic-search).

### AKNN (Approximate K-Nearest Neighbors)

Algorithms that find the K most similar vectors to a query vector, trading perfect accuracy for dramatic speed improvements. Antfly's dense `embeddings` index uses AKNN for fast, memory-efficient vector search on [embeddings](#embeddings).

**Key techniques used in Antfly's AKNN implementation:**

- **HBC (Hierarchical Balanced Clustering)**: Vectors are organized into a tree of balanced clusters whose leaves are posting lists. A query runs a beam search down the centroid tree, scans the selected leaves, then exact-scores only the candidates whose quantization error bounds overlap the result cutoff. Large indexes route through a flat exact-centroid directory instead of the tree. The only public tuning knob is `search_effort` (0 to 1, default 0.5).
- **RaBitQ**: A quantization method with a theoretical error bound. Antfly stores each vector as a 1-bit-per-dimension code of its residual from the leaf centroid and keeps full-precision vectors for the final rerank.
- **SPFresh**: Antfly applies SPFresh-style maintenance policies to HBC, such as lazy centroid refresh and local posting split and merge, so routine inserts and deletes stay local and never trigger a full rebuild. It is not a separate index type.

Hardware acceleration via [SIMD](#simd) speeds up distance calculations.

See: [FAISS](https://github.com/facebookresearch/faiss) | [ANN Benchmarks](http://ann-benchmarks.com/) | [SPANN Paper](https://arxiv.org/abs/2111.08566) | [RaBitQ Paper](https://arxiv.org/abs/2405.12497) | [SPFresh Paper](https://arxiv.org/abs/2410.14452)

### Algebraic Index

An index type that derives typed fields from the table schema and maintains declared exact aggregate recipes (`aggregates`) as materializations. Eligible queries reuse a complete materialization instead of scanning. The design treats aggregation as a fold over algebraic structures such as monoids, groups, and semirings.

See: [Algebraic design](https://github.com/antflydb/antfly/blob/main/zig/ALGEBRAIC.md)

### Facetting

Organizing search results into categories (facets) based on document attributes. Facets let users filter results by category, date range, author, or other fields. In Antfly, facets come from a query's `aggregations` (terms, range, histogram, date histogram, and geo) over the full-text index. See [Full-Text Search](#full-text-search--bm25).

See: [Faceted Search (Wikipedia)](https://en.wikipedia.org/wiki/Faceted_search)

### Full-Text Search & BM25

**Full-text search** indexes and queries the complete text content of documents. Unlike database queries on specific fields, full-text search handles natural language queries, typos, synonyms, and relevance ranking.

**BM25** is the ranking function used for scoring documents based on term frequency and document length. BM25 improves on TF-IDF by accounting for term saturation and document length normalization.

Antfly's full-text index (`zig/pkg/antfly-embedded/src/search`) is implemented natively in Zig as a Lucene-style segment index, using an FST-based term dictionary and roaring-bitmap posting lists to provide BM25 ranking, language-aware [tokenization](#tokenizers), [faceted search](#facetting), and highlighting.

See: [Introduction to Information Retrieval](https://nlp.stanford.edu/IR-book/) | [Okapi BM25 (Wikipedia)](https://en.wikipedia.org/wiki/Okapi_BM25) | [BM25 Paper](https://www.staff.city.ac.uk/~sbrp622/papers/foundations_bm25_review.pdf)

### Graph Index

An index type that stores typed, directed edges between documents, from document fields or from relation [artifacts](#enrichments-artifacts--asset-producers) extracted by enrichments. Queries can traverse, list neighbors, find shortest paths, and match patterns; optional node summaries enable tree navigation in the Retrieval Agent.

See: [Graph Navigation](/docs/guides/graph-navigation) | [Graph design](https://github.com/antflydb/antfly/blob/main/zig/GRAPH.md)

### Hybrid Search

Combining multiple search approaches - typically [BM25](#full-text-search--bm25) (keyword) and [vector](#aknn-approximate-k-nearest-neighbors) (semantic) search - to get the benefits of both. Keyword search excels at exact matches; vector search handles [semantic similarity](#semantic-search). Antfly merges results using [RRF](#rrf-reciprocal-rank-fusion) or [RSF](#rsf-relative-score-fusion) fusion.

See: [Hybrid Search](/docs/guides/hybrid-search) | [Hybrid Search Explained](https://weaviate.io/blog/hybrid-search-explained)

### Indexing

The process of analyzing documents and building data structures for efficient search. Indexes trade storage space and write-time processing for fast query performance. Antfly's index types are [`full_text`](#full-text-search--bm25) (BM25), [`embeddings`](#aknn-approximate-k-nearest-neighbors) (dense or [sparse](#sparse-vectors--splade) vectors), [`graph`](#graph-index), [`algebraic`](#algebraic-index), and [`relational`](#relational-tables).

See: [Document Engine](/docs/guides/document-engine)

### Late Interaction (ColBERT & MaxSim)

A scoring method that keeps one vector per token for both query and document and sums, over query tokens, each token's best match in the document (MaxSim). In Antfly, late interaction is a [reranking](#rerankers) method: ColBERT-style models served by Antfly Inference rerank candidates. It is not an index type.

See: [ColBERT: Efficient and Effective Passage Search](https://arxiv.org/abs/2004.12832)

### React Components

`@antfly/components` is a React library for search interfaces on Antfly: `QueryBox` and autosuggest, facet filters, results and pagination, `AnswerResults` for streamed Retrieval Agent answers, and `ChatBar` for multiturn chat.

See: [React Antfly](/docs/ui/react-antfly)

### RRF (Reciprocal Rank Fusion)

A fusion method that combines ranked lists from different retrieval systems by scoring each result `1/(k + rank)`. RRF is Antfly's default merge strategy for [hybrid search](#hybrid-search). The constant `k` is `rank_constant` (default 60), and per-index `weights` scale each list's contribution.

See: [Reciprocal Rank Fusion outperforms Condorcet and individual Rank Learning Methods](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf)

### RSF (Relative Score Fusion)

A score fusion method that normalizes and combines actual scores (not just ranks) from different retrieval systems. RSF can better preserve score magnitude information compared to [RRF](#rrf-reciprocal-rank-fusion) but requires careful score normalization across different scoring functions. Antfly's RSF min/max-normalizes scores within `window_size` and applies the same per-index `weights` as RRF.

### Semantic Search

Search based on meaning rather than exact keyword matching. Semantic search uses [embeddings](#embeddings) to find conceptually similar content even when different words are used. "Car repair" can match documents about "automobile maintenance" through shared semantic meaning. Powers the vector component of [hybrid search](#hybrid-search).

See: [Semantic Search with Sentence-BERT](https://www.sbert.net/examples/applications/semantic-search/README.html)

### Sparse Vectors & SPLADE

Vectors in which most dimensions are zero, each nonzero dimension a weighted vocabulary term. SPLADE models produce them from text, which gives learned keyword matching. An `embeddings` index with `sparse: true` stores them in an inverted index instead of the dense HBC index.

See: [SPLADE Paper](https://arxiv.org/abs/2107.05720)

## Distributed Systems

### 2PC (Two-Phase Commit)

A distributed transaction protocol that ensures all participants in a transaction either commit or abort together. Antfly runs coordinator-driven 2PC over write intents with optimistic concurrency control (OCC): read versions are validated at commit, and a conflict returns 409. Clients use stateless `POST /transactions/commit` or server-managed sessions (`/transactions/begin`) with savepoints, and the protocol is model-checked in [TLA+](#tla).

See: [Transaction TLA+ spec](https://github.com/antflydb/antfly/blob/main/zig/specs/tla/AntflyTransaction.tla) | [Two-Phase Commit (Wikipedia)](https://en.wikipedia.org/wiki/Two-phase_commit_protocol)

### Autoscaling

Automatically adjusting system resources based on load. When enabled (it is opt-in), Antfly's Kubernetes operator scales data nodes on CPU and memory utilization within configured minimum and maximum replica bounds, and inference pools scale through a Kubernetes HPA. Compare with [Autosharding](#autosharding), which handles data growth.

See: [Kubernetes HPA](https://kubernetes.io/docs/tasks/run-application/horizontal-pod-autoscale/)

### Autosharding

Automatically splitting data partitions ([shards](#sharding)) when they grow too large and merging them when they shrink. Antfly splits and merges shards by size (`max_shard_size_bytes`, default 64 MiB) once you opt in by setting the node config key `disable_shard_alloc: false`; it defaults to `true`.

### Hot Standby

A Postgres-style high-availability mode: a single primary streams its WAL to read-only standbys (`antfly standby`), with replication slots for WAL retention and explicit promotion with fencing. It is an alternative to Raft quorums for read replicas, disaster recovery, and online upgrades. Point-in-time recovery is not supported; backups restore a selected backup snapshot.

See: [Hot standby design](https://github.com/antflydb/antfly/blob/main/zig/HOT_STANDBY.md)

### Raft & Multiraft

**Raft** is a consensus algorithm that ensures multiple nodes agree on a sequence of operations, providing strong consistency in distributed systems. Raft uses leader election and log replication. Antfly implements its own Raft consensus natively in Zig (`zig/lib/raft`, `zig/pkg/antfly/src/raft`), architecturally inspired by `etcd/raft`'s deterministic core and Dragonboat-style multi-group hosting. Node-to-node Raft traffic uses HTTP.

**Multiraft** extends this by using multiple independent Raft consensus groups. Unlike single-Raft systems where one group handles all data, Multiraft assigns separate Raft groups to different data partitions ([shards](#sharding)). This enables parallel operations, fault isolation, and independent scaling. Antfly uses Multiraft with separate groups for metadata and each storage shard.

See: [In Search of an Understandable Consensus Algorithm](https://raft.github.io/raft.pdf) | [Raft Visualization](https://raft.github.io/) | [etcd/raft](https://github.com/etcd-io/raft) | [TiKV Multi-Raft](https://tikv.org/deep-dive/scalability/multi-raft/)

### Sharding

Horizontally partitioning data across multiple nodes or storage units. Antfly partitions each table into shards by key range; `num_shards` sets the initial count, and `replication_factor` (default 3, maximum 5) sets how many replicas each shard keeps. See also [Autosharding](#autosharding).

See: [Shard (Wikipedia)](https://en.wikipedia.org/wiki/Shard_(database_architecture))

### Tables, Shards & Raft Groups

A **table** is a named collection of documents with a schema and indexes, split into key-range **shards**. In a distributed deployment each shard is replicated by its own data **Raft group**, while a separate **metadata group** holds cluster topology, schemas, and table definitions. Lite storage has no Raft, and `object` tables allocate no data Raft groups.

See: [Architecture](/docs/architecture)

## Deployment & Storage

### Antfly Lite (.aflite)

Antfly's single-file storage engine: one portable `.aflite` file with one writable owner, opened directly by an embedded application or served by a standalone server, and managed with the `antfly lite` CLI. It uses its own page engine rather than the [LSM tree](#lsm-tree).

See: [Antfly Lite](/docs/guides/lite) | [Lite design](https://github.com/antflydb/antfly/blob/main/zig/LITE.md)

### Deployment Modes

Which processes run, chosen independently of the [storage engine](#storage-engines). `embedded` opens Antfly inside an application with no server; `standalone` runs one process that owns metadata, data, APIs, and inference; `distributed` splits metadata and data nodes for horizontal scale; and `serverless` (in progress) decouples compute from object storage.

See: [Deployment and storage design](https://github.com/antflydb/antfly/blob/main/zig/STORAGE.md)

### Document Storage

Storing data as self-contained JSON documents rather than rows in tables. Documents can have flexible schemas and nested structures. Antfly stores documents with automatic indexing of fields.

### Linear Merge

A stateless way to sync sorted records from an external source. Antfly's linear merge (`POST /db/v1/tables/{table}/merge`) takes a sorted page of source records and performs a three-way sync over that key range: it inserts new keys, updates changed ones, and deletes Antfly keys missing from the page.

### LSM Tree

The log-structured merge tree behind the `local` [storage engine](#storage-engines) (`zig/pkg/antfly-embedded/src/storage/lsm_backend`). Writes land in a WAL-backed memtable, then flush to immutable sorted runs (`runs/<id>.tbl`, often called SSTables) tracked by a manifest and compacted in the background. Each [shard](#sharding) has its own storage instance; [Antfly Lite](#antfly-lite-aflite) uses its own engine instead.

See: [LSM-Tree (Wikipedia)](https://en.wikipedia.org/wiki/Log-structured_merge-tree)

### Storage Engines

Where durable state lives, chosen independently of the [deployment mode](#deployment-modes). `lite` is a single `.aflite` file, `local` is a directory of [LSM](#lsm-tree) shard and metadata storage, and `object` keeps durable data in object storage.

See: [Deployment and storage design](https://github.com/antflydb/antfly/blob/main/zig/STORAGE.md)

### WAL (Write-Ahead Log)

A durability mechanism where operations are written to a sequential log before being applied. If the system crashes, the WAL enables recovery by replaying logged operations. Antfly keeps a [Raft](#raft--multiraft) log WAL and an [LSM](#lsm-tree) WAL for mutable state, and [hot standby](#hot-standby) replicates by streaming the WAL to standbys.

See: [Write-Ahead Logging (Wikipedia)](https://en.wikipedia.org/wiki/Write-ahead_logging)

## Technologies & Frameworks

### A2A (Agent2Agent)

An open protocol for agents to discover and call each other. Antfly serves A2A at `POST /a2a` with an agent card at `/.well-known/agent-card.json`, advertising its native [agents](#agent) as skills.

See: [A2A design](https://github.com/antflydb/antfly/blob/main/zig/A2A.md) | [A2A Protocol](https://a2a-protocol.org/)

### GGUF & safetensors

Model weight file formats. GGUF is the single-file format from the llama.cpp/ggml ecosystem, often quantized; safetensors is Hugging Face's safe tensor serialization format. [Antfly Inference](#antfly-inference) runs both natively, alongside [ONNX](#onnx-open-neural-network-exchange).

See: [Model Downloads](/docs/guides/model-downloads) | [GGUF](https://github.com/ggml-org/ggml/blob/master/docs/gguf.md) | [safetensors](https://github.com/huggingface/safetensors)

### JSON Schema

A vocabulary for annotating and validating JSON documents. JSON Schema defines the structure, types, and constraints of JSON data. Antfly uses JSON Schema for table schemas with custom `x-antfly-*` extensions for indexing configuration.

See: [JSON Schema](https://json-schema.org/) | [Understanding JSON Schema](https://json-schema.org/understanding-json-schema/)

### MCP (Model Context Protocol)

An open protocol that lets AI clients call tools exposed by a server. Antfly's MCP surface, over streamable HTTP, exposes exact table, index, document, and query operations; natural-language planning stays in the native [agents](#agent).

See: [n8n AI Agent over MCP](/docs/guides/n8n) | [MCP design](https://github.com/antflydb/antfly/blob/main/zig/MCP.md) | [Model Context Protocol](https://modelcontextprotocol.io/)

### ONNX (Open Neural Network Exchange)

A standard format for representing machine learning [models](#model-mlai). ONNX enables models trained in different frameworks (PyTorch, TensorFlow) to run in a common runtime. Antfly Inference parses `.onnx` graphs itself and executes them on its native kernels, with no external ONNX runtime, providing [embedding](#embeddings), [chunking](#chunking), [reranking](#rerankers), and generation without external API calls. Its experimental WASM/WebGPU browser backend also uses the native importer rather than ONNX Runtime Web.

See: [ONNX](https://onnx.ai/)

### OpenAPI Specification

A standard for describing REST APIs in a machine-readable format. Antfly's APIs are defined in OpenAPI under `specs/openapi/`. The Go, TypeScript, and Python SDKs are hand-written clients over generated code, and the Rust SDK is generated end to end.

See: [SDKs](/docs/sdks) | [OpenAPI Specification](https://spec.openapis.org/oas/latest.html)

### SIMD

**SIMD (Single Instruction, Multiple Data)** is a CPU feature that processes multiple data elements in parallel with one instruction. Antfly uses Zig's portable `@Vector` SIMD, AVX2/AVX-512 kernels on x86, and NEON on ARM for fast vector distance calculations in [AKNN](#aknn-approximate-k-nearest-neighbors) search and for inference kernels.

See: [Intel Intrinsics Guide](https://www.intel.com/content/www/us/en/docs/intrinsics-guide/index.html) | [ARM NEON](https://developer.arm.com/Architectures/Neon)

### TOON (Token-Oriented Object Notation)

A compact encoding of JSON for LLM prompts that declares the fields of uniform arrays once and lists one row per line. The Retrieval Agent renders retrieved documents into its generation prompt as TOON by default, so more documents fit in the same context.

See: [TOON format reference](https://github.com/antflydb/antfly/blob/main/docs/reference/toon-format.md)

### XLA (Accelerated Linear Algebra)

An open-source ML compiler, now developed under the OpenXLA project, that targets CPUs, GPUs, and TPUs through the PJRT runtime interface. Antfly Inference has an experimental PJRT/XLA backend.

See: [OpenXLA](https://openxla.org/)

## Testing & Verification

### TLA+

A formal specification language for modeling concurrent and distributed systems and model-checking their invariants. Antfly's TLA+ specs cover the Raft, 2PC transaction, shard split, snapshot transfer, and LSM lifecycle protocols.

See: [Antfly TLA+ specs](https://github.com/antflydb/antfly/blob/main/zig/specs/tla/README.md) | [TLA+](https://lamport.azurewebsites.net/tla/tla.html)

### VOPR

Antfly's deterministic simulation testing platform. It runs unmodified production code on a virtual, fully controlled I/O layer, injects faults, and replays any failing history exactly from its seed. Scenarios cover metadata, transactions, Raft, storage, standby, backups, and a full cluster.

See: [VOPR design](https://github.com/antflydb/antfly/blob/main/zig/VOPR.md)

## Other Concepts

### Scraping & Remote Content

Extracting content from web pages or documents for indexing. Antfly supports automatic download and processing of content from URLs (http/https/s3/file) with built-in SSRF prevention and content validation for secure remote processing of images, PDFs, and HTML.
