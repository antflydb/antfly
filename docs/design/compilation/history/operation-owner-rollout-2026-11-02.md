# Operation owner rollout qualification (2026-11-02)

Image/PDF operation ownership and lake execution ownership remain opt-in. This increment adds durable qualification, not a default rollout or a claim about Release performance.

## CI admission and profiles

`.github/workflows/zig-owner-qualification.yml` is called by the approved PR controller for Zig/full validation. It reuses the existing approval admission check and checks out the exact approved head. The PR aggregate requires this workflow to succeed. A small diff job skips owner jobs for changes outside Zig and these gate files. Main pushes, merge queues, scheduled qualification and manual runs use the same workflow.

Hosted Ubuntu 24.04 and macOS 15 run negative policy tests and compile the opaque PDF consumer without scheduling its provider. Actual provider tests run on the existing Linux x86_64 `arc-antfly-heavy-runtime` profile (24 GiB pod, 20 GiB compiler budget); the existing owner memory reservations are preserved. A manually selected self-hosted Apple Silicon profile must have at least 36 GiB of actual memory. No hosted 7 GiB runner is represented as able to admit an 8 GiB media provider or a 20–28 GiB production owner.

The heavy Linux gates cover independently linked source/native image and retained PDF equivalence, complete lake ABI/source fixtures, the opaque read-session fixture, production archive codec/builder ownership, and actual S3-compatible catalog reopening. Full/scheduled/manual qualification additionally runs media, lake and public mutation invalidation matrices. The optional self-hosted Mac matrix runs the native media/lake/read-session fixtures, ownership invalidation matrices, and paired lake runtime probes. Real S3 qualification reuses the functional job's existing linked provider/test compilation. The existing executing-workflow dependency bootstrap supplies checksum-verified source dependencies.

These jobs are configured, not remotely executed by this local change. Supported platform coverage is a CI requirement; local macOS results do not substitute for Linux or a self-hosted Mac production qualification.

## Real S3-compatible fixture

`scripts/test-lake-s3-integration.sh` builds official MinIO source at exact module version `v0.0.0-20250422221226-0d7408fc9969`, verifies its pinned Go module checksum, and records source/build provenance and binary hash. Its binary, Go build/module caches, private data and private configuration remain inside the worktree's Zig cache. The throwaway server binds loopback, uses fixture-only credentials and enables bucket versioning. Cleanup stops only the process it created and removes its private run directory.

The environment-gated Zig test creates real Parquet rows, Iceberg Avro data/manifest-list objects, managed catalog objects and native index artifacts through actual S3-compatible I/O. It admits snapshot 7, advances authoritative HEAD to snapshot 8 whose manifest is absent, and requires a fresh native execution owner to finish snapshot 7 from the retained metadata. Another fresh worker resumes the checkpoint. Missing authoritative HEAD, retained metadata from another table UUID, and a durable retired snapshot must fence the retained metadata reopen. The retirement test advances the explicit GC timestamp past the lease/grace window; it does not wait through a real cloud retention lifecycle. An exact completion marker is required; an environment-gated skip cannot pass the harness.

This is local MinIO S3-compatible transport/catalog/pin qualification. It is not an AWS/GCS, cloud IAM, retention lifecycle, eventual consistency, injected network fault or production cloud qualification.

The first real manifest read exposed an existing Debug stack overflow: `decodeBlockAlloc` reserved an 8 MiB zstd window in a shared frame, including null-codec calls. The decoder now allocates/frees that bounded workspace only for zstd. All 17 focused Avro tests pass, including actual null/zstd decoding on a 1 MiB worker stack. Both hosted platforms execute this regression in CI.

## Whole-attempt runtime evidence

`lake-execution-runtime-probe` is a normal executable, linked to the same independently compiled non-test provider archive as the ABI fixture. Both source and provider compile with `builtin.is_test=false`; an exported test-only scalar getter reports the provider's actual compile mode, and the receipt rejects either side being a test build. Source/provider storage owner options match. It constructs four Parquet inputs and all five native index families through source and independently linked native execution paths. It exercises a cold attempt, a checkpoint resume, and a fifth-file incremental append. It validates the candidate catalog generation, complete declaration count and checksummed artifact readability before emitting observations.

`zig/tools/check_lake_execution_runtime.py` requires every source/native phase and round. It records physical execution wall time, control admission time, their combined attempt time, real charged working-set quota peaks, checkpoint count, retained declaration root count and API cache provider reads/bytes/hits/misses. Provider-private cache counters and internal artifact file reuse are not claimed. It rejects skipped, partial, duplicate and incorrect-workload receipts and reports per-phase medians and native/source physical and combined attempt ratios. Raft/network publication latency is outside this isolated attempt probe. The initial test-object source oracle had `builtin.is_test=true` while its provider archive was false. Its roughly 35% local slowdown is asymmetric diagnostic evidence and is excluded from rollout acceptance. The corrected normal executable removes that compile-mode asymmetry. The probe uses the SMP backing allocator and alternates source/native order each round. The real quota owners still require every charged allocation to be released. Profiling the first successful 512-row smoke showed that `std.testing.allocator` allocation stack tracing dominated its runtime, so those diagnostic timings are not used for a rollout decision. CI runs four balanced paired rounds of a bounded normal-runner workload; Debug observations are not a Release SLA or a default rollout decision.

## Local receipts and remaining qualification

Pure checks pass: 13 existing image receipt/cache policy tests, four negative archive ownership tests, four runtime receipt tests, 17 Avro decoder/worker-stack tests, one concurrent family-attribution test, 48 callback/native/error ABI tests (one expected diagnostic), 11 independently linked I/O ABI tests, 210 approved PR controller policy tests, workflow actionlint, scoped license headers and shell syntax. The existing installed ten Debug archives pass the new ownership inventory.

The final real S3-compatible run passes seven tests with zero skips, failures or leaked test allocations; all 75 build steps pass. The attempt-cache replay also passes seven tests/75 steps. Its clean receipts are `.benchmark-results/compile-costs/lake-rollout-s3-final.log` and `lake-rollout-s3-attempt-cache.log`, with provenance/result under `.benchmark-results/lake-s3/`.

The corrected non-test runtime smoke passes 12 observations (four files ×128 rows, two balanced rounds). On the local contended macOS ARM64 host, total-attempt native/source median ratios are 1.368 cold, 1.206 checkpoint resume, and 1.303 incremental append. These are measured regressions, not an ABI-only cost attribution or rollout acceptance. Source resumes hit the API cache without additional API-provider reads; the native provider currently opens a fresh Source without that shared cache. Native API cache zeros do not measure native provider I/O. Private cache pointers do not cross ownership boundaries. This bounded attempt cache restores within-attempt reuse; it does not establish a material runtime win in the local smoke.

The pre-attempt-cache CI-sized non-test workload (four files ×1024 rows, four balanced rounds) passes all 24 observations, with total-attempt native/source ratios 1.273 cold, 1.286 resume and 1.166 append. They remain local contended Debug data.

Stage timing attributes under a millisecond each to provider Source reopening and store reopening, versus 1–2 seconds physical execution at the small workload. API admission is similarly around a millisecond. Those measurements do not support a large admission contract refactor as the local runtime fix.

An optional single-provider-quota probe retains the actual provider hard limit and peak counter. It does not establish a useful speedup; production keeps both existing limits. The first optional-mode harness run caught a result allocator mismatch in its cleanup, which was corrected; production allocator ownership was unchanged.

The I/O dispatcher experiment records around 7,850 foreign dispatches for cold/resume and 12,220 for append. A qualification-root-only switch/linear selection permits same-executable A/B while preserving caller I/O, errors, batch remapping, reader transfer and invalid-ordinal rejection. The second run reuses both cached executable and provider. The local normalized timings overlap without a material benefit; **the production dispatcher retains its original linear body**, and the switch stays qualification-only. The production archive guard rejects accidental alternate-dispatch inclusion. This is a tried/rejected optimization, not a performance claim.

Final family attribution covers the five physical writer families plus row identity, fragment preparation and spool work, with actual decoded-cache hits and declaration-root byte counters. It records executable hashes, compile modes and source manifests, and rejects authored compile-input changes during measurement. The family comparison located the structural cause: source writer worker-times overlap, while native writer times were individually shorter but serial. Strict `WorkingSetAllocator.headroom` lost optional capacity when it reached an allocator vtable created by another compilation unit; the physical pipeline conservatively declined parallel work.

The private lake contract is now v3. The caller issues a version/signature/return-layout-checked optional headroom query. A provider-local forwarding allocator exposes only that creator's current capacity to strict lake headroom composition. The provider still takes the minimum of its own current quota and the dynamically reported backing capacity. Unknown/low availability retains serial fallback, every allocation still forwards through the original allocator and both original hard limits, and no query is added to allocator allocation/free methods. The capability and wrapper are bounded to the complete synchronous attempt.

Tests reject version/layout/signature/null capabilities before callback (including a poisoned callback pointer), check dynamic remaining quota128→48→128, enforce nested hard-budget OOM, and preserve the existing cancellation/fence/foreign-error tests. The real S3v3 run passes ten tests with zero skips/failures/leaks and75steps. Auto/unknown/low each pass12 observations using the same executable: adequate creator capacity restores overlapping work and1.01–1.06 native/source ratios; unknown/low retain serial work and the previous~1.3–1.4 ratios. The CI-sized adequate-capacity run passes24 observations with unchanged authored-input manifests; local ratios are1.032 cold,1.044 resume,1.013 append. Qualification-only admitted-job counters additionally guard against mistaking a serial run for restored parallelism.

The principle is that foreign vtable identity is not a resource capability. Introspection belongs to the allocator creator; receivers consume checked coarse facts. A follow-up SQL boundary audit should apply that principle where evidence warrants, preserving the different conservative/tolerant semantics of existing SQL budget helpers rather than mechanically changing them. This fix is scoped to measured lake admission; it changes no SQL budget behavior. Remote Linux/self-hosted macOS gates remain unexecuted here. No Release benchmark or default rollout is claimed; both ownership defaults stay off.
