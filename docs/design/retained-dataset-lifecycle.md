# Retained dataset lifecycle

Follow-up to [time-series design #1540](https://github.com/antflydb/antfly/issues/1540).

## Resource and storage contracts

A retained dataset has a stable 32-byte identity, a kind (`records` or `summary`), immutable definition generations, a self-contained schema and its SHA-256 digest, an authorization-policy identity, logical retention, and local residence. Summary definitions additionally describe source identity/filter, dimensions, timestamp, a versioned UTC fixed-duration bucket/origin, measurement laws, and a correction window. Other timezone/calendar semantics are rejected until their decoder and planner contracts are implemented. Nanosecond coverage, origins, durations, and source sequences are decimal strings so JavaScript hosts preserve the full signed domain.

`serverless/datasets` implements the durable lifecycle boundary. Its catalog uses the existing `objectstore.transactional_store` conditional-root backend and immutable ordered pages. It does not introduce another metadata authority protocol. Each dataset has an independent permanent authority namespace. The catalog itself must be durably backed up and reachable by every serving host; moving segment contents does not move the catalog authority. Use shared object storage for a stateless/serverless deployment. Conditional ownership and exact-root publication prevent stale writers from advancing placement after an ownership change.

Definitions are immutable by generation. Evolution installs a new current definition and retains previous definitions/schemas. Existing segments continue to reference their original generation. Evolution establishes no new backfill coverage. The kind is stable across generations.

Segments contain a content digest/length, dataset/generation/schema identity, state-encoding version, half-open event coverage, source partition/incarnation/applied sequence, finalization state, and placement revision. Producers supply complete immutable segment contents. The operator does not certify that arbitrary supplied bytes were captured transactionally from a source table.

This layer accepts already produced record or aggregate-state segments. The native producer and decoder integrations described below build on this layer; Provisioned deployments mount summaries through a read-only SQL relation and a bounded JSON API. A closed summary can serve from its independent archive after source detachment. In particular, creating this resource does not make ordinary source-table TTL preserve historical aggregates. Hosts must establish those producer and retention proofs before connecting automatic source deletion.

## Placement and access

Location identities are separate from physical store bindings. A host supplies a stable physical-binding fingerprint; the first publication binds it durably and subsequent operations reject rebinding. URLs and credentials are not persisted in dataset metadata. The administrative operator derives the binding fingerprint from the supplied URI, so later invocations must use the same URI spelling for a location identity. Host applications should derive stable fingerprints from their own binding registry.

Access modes are `local`, `queryable`, and `restore_required`. At this storage boundary `queryable` means a host can obtain the immutable bytes directly without restore; it does not imply that the segment's encoding is automatically mounted as a SQL table. Decoder/version admission remains the query host's responsibility. Restore-required objects cannot acquire new read leases until restored.

Migration copies finalized segments only. It reads and SHA-256 verifies the complete source object, performs a conditional immutable destination create, reads/verifies the destination, and then publishes placement through exact-root CAS. Duplicate immutable uploads are accepted only after verification. A lost acknowledgement or a failed catalog CAS leaves the previous placement authoritative. Local and remote copies never become separate coverage entries.

A restore copies verified archive data into a local binding and publishes a new placement revision. It preserves the archive reference and does not authorize deletion of the archive. Repeated migration back to a retained archive can reuse its immutable object. Migrating between arbitrary remote locations or retaining an unbounded replica set is not part of the initial contract.

All object reads, copies, and metadata pages are bounded. Segment contents are limited to 16 MiB; producers split larger outputs into disjoint extents. Metadata rows retain the shared coordinator's 32 KiB bound. Interrupted uploads can leave unreferenced content-addressed objects; this release never automatically deletes an object merely because a catalog publication failed. A bounded orphan collector must use a publication barrier and an inventory of protected references before it is enabled.

## Coverage and planning

The catalog indexes non-overlapping extents by definition generation, source partition/incarnation, and ordered row-key end. A row key combines sign-biased fixed-width event time with the canonical-dimension digest. Optional explicit spans split large buckets across bounded files; absent spans retain the legacy whole-time extent and physical index key. Publication checks the first extent ending after its start; because existing extents are disjoint, this proves non-overlap without scanning history. The locator and segment metadata commit atomically.

`planRange` seeks directly into the requested partition/generation. It requires contiguous complete coverage, exact segment boundaries, and an explicit output bound. Missing history is an error, not an empty aggregate. `planCoveringRange` additionally selects complete files covering a narrower request; a decoder must filter their rows to that exact requested range. Explicit empty-state segments can certify empty coverage. Different source incarnations and definition generations are never implicitly merged.

A range plan is a preparation result, not a read capability. A host must acquire each selected segment lease and verify its contents before use. Bounded materialization verifies the full result before exposing rows; streaming execution must report a terminal failure if a later file cannot be verified, and must never report successful completion for partial coverage. It must enforce the current dataset authorization policy, admit schema/state decoders, choose authoritative source topology, and merge aggregate states through their declared laws. This catalog does not manufacture a cross-partition transaction snapshot from independent positions.

## Reader-safe eviction and deletion

Read acquisition registers a pin and validates the segment in one metadata transaction. Migration can proceed while an old local reader remains active. Local eviction first proves no unexpired pins reference that local copy and publishes a retirement barrier, then deletes the object in a resumable second step. New readers use the authoritative remote placement.

Pins have a ten-minute maximum lifetime, a thirty-second collection grace, and a host suspend-inclusive authority deadline. A wall-clock rollback cannot extend a live read. Acquisition cleans expired pins within a bound of 64 active pins per segment. Hosts should share leases across requests where appropriate; this is not one durable consumer per browser.

Logical expiration is based on event-range end plus the definition generation's retention. Expired segments cannot acquire new read leases even if a dependency keeps their bytes physically retained. Existing admitted snapshots remain bounded by their original leases. Local residence is a policy target exposed to a scheduler, not permission to delete logical history or a mandatory minimum residence time.

Durable dependency holds prevent permanent retirement. Hold acquisition races atomically with the retirement barrier; a retired segment cannot gain new dependencies. Releases compare exact consumer/generation identity so an old worker cannot clear a replacement hold. A host must authorize hold/release operations and release a hold only after the downstream requirement is satisfied.

Retirement requires logical expiration, finalized state, no pending old-local reclamation, no dependencies, and no live readers. It fences new readers before collection. Collection deletes current and retained archive copies independently, records completion, and keeps a tombstone to prevent stale publication retries from resurrecting history. Event-ordered compaction replaces fully collected tombstones and their expired pins with one durable retirement floor per source partition/incarnation/definition generation. Publication rejects any extent crossing below that floor; cleanup cannot grow one permanent record per expired segment indefinitely. Producers must never reuse a segment identity for different contents/coverage. Ambiguous delete acknowledgements resume safely.

`requireSourceReclamation` is the distinct coverage proof for a required summary: matching dataset/definition generation, exact source lineage, an incorporated sequence at least as new as required, finalized non-retired state, and covering event extent. It does not authorize local eviction, archive expiration, or deletion of the summary itself. Connecting it to raw TTL requires the native producer/commit integration described above.

## Native maintenance core status

`antfly-embedded/storage/retained_series.zig` now supplies a transactional state machine for the native integration. It takes normalized before/after rows and a canonical source-command time/sequence. Source rows, maintained states, replay progress, and keyed feed frames must share one serialized write transaction with read-your-writes cursor semantics. An error requires aborting the entire transaction. The module never commits transactions, reads a host clock, or writes remote objects.

The core includes count/sum/average states, ordered support for correction-aware min/max, fenced bounded backfill, explicit earliest complete coverage, TTL finality checks, indexed bucket reads, typed count projection, bounded keyed replay, logical-retention removals, and bounded cleanup of backfill/extrema support. AVG retains sum and count for later composition. Feed pressure evicts replay history and requires a fresh snapshot rather than holding raw data or rejecting source writes because a browser fell behind. Reads and their initial replay cursor must come from the same immutable transaction; the host must retain that visibility cut across paginated snapshot reads.

Native primary commits now capture coalesced before/after rows and maintain summaries in the same storage transaction. A dedicated durable source sequence fences replay independently of derived-index replay positions. Capture projects only referenced packed-row columns and caches immutable layouts per schema version; typed dimension canonicalization and COUNT(column) distinguish SQL null from JSON null. Registry activation uses tagged cache epochs so a stale negative lookup cannot disable capture.

Private install/backfill/tick/cleanup/close controls are admitted through the native lifecycle transaction and negotiated Raft batch protocol version 32. Retention read admission uses a separate version 33 barrier, persists bucket expiry boundaries without emitting replay events, and coalesces steady-state reads to one admission per interval. Native transaction preparation now reserves exact before/after contributions with the intent vote, preserves per-bucket extrema evidence across the correction deadline, and charges reservation metadata to intent admission. The total prepared source key count and before/after byte bounds apply across all prepare requests in the transaction. Commit, abort, and no-op resolution retire those reservations atomically; an already-admitted clock cannot move backward at commit. Ordered owners require the replicated prepare-admission timestamp, while local ingress resolves it once before retries. Native TTL filters individual candidates against readiness/finality and preserves historical aggregates on expiration. Coordinated foreign-key TTL carries explicit per-row expiration provenance through closure planning, participant routing, private versioned transport and prepared contribution proofs. CASCADE deletes inherit expiration; surviving SET NULL writes retain ordinary correction semantics. Independent blocked roots do not starve eligible siblings. Explicit corrections retract mutable contributions. A summary's own logical expiry releases its dependency on old source evidence even while physical cleanup is pending.

A generation can close only after backfill is ready and every prepared reservation has drained, including no-op intents. Closure freezes future-dated observations as well as older buckets, releases source-write restrictions for that generation, and preserves independently fenced historical reads. A replacement generation has its own coverage admission and backfill. Closed generations remain locally owned until archive/publication handoff completes; closing alone does not authorize source-owner deletion.

Close admission is a separate durable step before waiting for prepared contributions. It rejects new prepare votes and direct contribution changes, while honoring exact prepare retries and resolutions of existing votes. Callers receive a retryable HTTP 503 or SQL `55P03` while draining. Correction-window and coverage failures are definitive conflicts; malformed rows and numeric overflow are definitive input errors. Remote transaction responses preserve an unknown or committed outcome ahead of these typed errors.

Native summary resource creation now commits a producer plan with its source dependency. The plan binds the exact dataset, generation, definition, source, and topology membership. Its per-owner journal uses revision checks and an ordered cyclic work index; cancellation stops registration, requires revocation of every registered owner, and retains cleanup work independently of catalog-name index rebuilds. Plan, owner, and work rows are included in metadata Raft snapshots. A delayed installation is fenced by a native revocation tombstone, including when cancellation arrived before installation. Catalog publication cannot promote an unready plan or detach a source using an arbitrary descriptor receipt. Metadata protocol 86 gates this contract. A fixed-size registration Raft command derives at most 64 owners per page from metadata, using an ordered range index and verifying the accumulated owner membership against the frozen digest before completing registration. Stale registration commands cannot reopen cancelled plans. Registration RPCs, independent receipt verification, and the production supervisor still need to connect these journal primitives to native controls.

The archive state codec uses an endian-stable versioned format (encoding 2, with encoding 1 reads retained), preserving integer counts and f128 sum/count state without JSON rounding. Its explicit source-closure receipt permits immutable future observations; header encoding must match the segment descriptor. Immutable definition/source identity, complete/finalized coverage, ordered unique keys, finite metrics, size limits and malformed/trailing bytes are validated. Ordered key spans let a high-cardinality bucket span multiple bounded files. Coverage planning, overlap rejection and retirement floors operate on those same spans, while legacy whole-time extents retain their original physical metadata keys. Covering-range plans permit narrow queries inside larger files; the archive reader acquires current-placement leases, verifies checksums, decodes states and filters exact requested row keys. Missing coverage and restore-required storage remain explicit errors.

The private native reader holds one immutable visibility cut across pages and captures the initial replay cursor from that cut. It retains its owner and row-policy admission, rechecks policy admission before returning pages and has a bounded lifetime. The public serving adapter uses this private bridge for native summary partitions.

The following integration work remains required before the feature can be advertised as complete:

- Metadata orchestration for topology handoff and definition/source closure. Direct split/merge admission and transactional range/transfer metadata now reject coverage-changing transitions while retained bindings exist. Owner open and unpublished import publication validate the retained registry against the physical namespace; an archive copied into a different owner cannot silently become a producer. These guards preserve coverage until the staged lineage handoff is implemented; they do not constitute resharding support.
- Stalled-work observability and standalone scheduling. Private callable controls alone are not automatic maintenance. A bounded allocation-free planner now rotates backfill, retention ticks and marker collection fairly across admitted bindings; durable marker-cleanup completion avoids repeated empty commands. Cluster data leaders now schedule indexed registration, backfill, retention ticks and cleanup through bounded maintenance jobs. Cluster data leaders also stage closed archive pages through the configured shared artifact store. Standalone scheduling still requires host integration.
- The legacy direct intent API cannot choose a local clock on an ordered owner; such owners use the timestamped transaction-preparation path. Local bound/coordinator preparation uses its chosen transaction timestamp.
- Source split, merge and restore still require a separate lineage handoff. Source DROP is allowed after verified detachment.
- Replicated freeze/publication/eviction receipts connecting native states to the object catalog. The independent catalog now commits each verified closed-state page with its resume frontier and seals the complete empty tail separately. The metadata leader verifies the sealed receipt through a read-only connection before authorizing bounded native reclamation. The dataset retains its source dependency until every registered owner acknowledges reclamation. Native/archive ownership must select exactly one authoritative extent, and archived expiry must still emit subscriber removals.
- Durable external sinks, and a streaming SQL subscription statement. The current subscription API uses explicit cursor polling and holds no source retention state.

`retained-series-test`, `retained-series-native-test` and `retained-series-protocol-test` cover the transactional state machine, actual primary-write/capture/lifecycle integration and Raft capability/delegate gates. `retained-dataset-test` covers object placement, leased reads, disjoint span planning, retirement, and archive decoding through cold storage. These tests do not certify the unfinished public surfaces or unsupported source transitions.

## Integration sequence

1. Durable resource, immutable definitions/schema, indexed coverage, verified placement, reader pins, holds, and administrative operations (this change).
2. Native snapshot/backfill producer and committed correction maintenance, with source admission/finalization fencing and transactional progress publication.
3. Source TTL/replay/support dependencies, including lease-owned background scheduling and bounded stalled-retention behavior.
4. Aggregate decoder admission and SQL/JSON summary/history queries, with topology and authorization proof gates.
5. Resumable subscriptions, followed by optional alert consumers and an outbox.

The lifecycle API is designed for ordinary retained records as well as aggregate-state segments. It must not be advertised as automatic migration of an existing live table until the source integration and query routing stages are implemented and qualified.

## Serving and ownership integration constraints

Metadata must register the independent dataset and its immutable source binding before any native binding is activated. A transactionally maintained inverse source index prevents source deletion from racing that activation. A separate bounded work index selects enabled dataset/owner pairs for leader maintenance; supervisors must not open every raw table to discover whether a producer exists. Creation and recovery reconcile the same durable activation state instead of relying on an HTTP request to finish every owner.

The private catalog protocol exposes `retained_owner_register` and `retained_owner_read`. Registration requires a body-bound administrative grant, a current immutable plan/revision, and a bounded page of at most 64 owners derived from metadata. The service checks coordinated decoder readiness before admission. Registration never accepts caller-authored physical owners or receipts. Cluster and standalone execution persist the same journal command; progress does not invalidate unrelated routing caches.

Owner reads require a body-bound setting-authority read grant. Work selection performs one cyclic seek over the ordered owner work index. An exact read binds resource, generation, plan identity, group and owner revision. The response captures the plan, owner, resource, current source schema and physical range in one metadata transaction, checking source identity/schema, frozen topology membership and the native namespace digest. Stale exact requests fail instead of silently reading a replacement owner. These catalog RPCs do not execute native controls, attest native progress or authorize source detachment; those require the separate native control and verified acknowledgement path.

Standalone runs the same indexed owner lifecycle from its maintenance worker. The standalone catalog pins the native root and signing key before accepting a summary. The local storage owner applies each bounded command in its own durable transaction, and metadata verifies the signed observation against the pinned root and current owner revision. Closing uses the same read-only sealed-export verifier as clustered metadata before revocation and reclamation. Standalone HA deployments require a separate retained-owner handoff protocol.

A definition closes at a committed source cut after all of its prepared contributions have drained, including no-op reservations. Closure makes future-dated observations immutable as well as older buckets. The next generation has its own coverage admission and backfill; closing a generation never certifies new coverage for its replacement. Closed local states still own their physical namespace until verified archive publication and reader-safe reclamation complete. Native closure alone cannot authorize deleting the source owner's directory.

Archive publication needs an authoritative extent receipt, independent of object upload success. Publish and verify complete bounded files first, then commit the native-to-archive authority transition. Readers select one authoritative placement at their captured cut. A missing archive cannot fall back to stale local payloads, and a local replica never contributes a second partial aggregate. Source deletion can release its dependency only after every required retained extent is independently owned or logically expired; a closed-source proof must also describe the complete empty tail beyond its last observation.

Evicting native metric payloads must preserve logical-expiration delivery. Retaining a row-sized native payload solely to emit a later removal defeats cold placement. The public change protocol should support an aligned `expire_before` watermark alongside keyed upserts/removals, with a durable monotonic retention frontier. The serving session applies that frontier to its bounded result state even after the closed producer owner has been retired. Ordinary placement changes do not change query results or create additional rows.

Cross-partition subscriptions require mergeable partial states, including AVG's sum/count, and cannot resume from global scalar values plus a partition vector alone. A bounded serving session may retain those partials and a replayable output sequence; an authenticated opaque token binds its query, generation, schema, authorization, owner incarnations and replay position. Session loss, replay loss or changed authority requires an explicit reset and fresh snapshot. Browser sessions hold neither source TTL nor durable replication slots. Managed durable sinks remain a separate future `CREATE SUBSCRIPTION` facility.

Moving windows need both removal and admission of rows as time advances. Future observations can enter a window without another source mutation. The serving operator must read newly entered ranges and retain per-key source positions so a range read cannot skip unrelated feed events or let an older event overwrite a newer partial. Authorization is rechecked throughout serving, and independently captured partition cuts must never be presented as a global transaction snapshot.


## Query and subscription surface

On a provisioned cluster or single-writer standalone node with configured S3 or GCS artifact storage, create a summary with `POST /db/v1/databases/{databaseName}/namespaces/{namespaceName}/datasets/{datasetName}`. Creation requires dataset and source table administration. Status reports `activating`, `active`, `closing` or `closed`. Automatic activation starts from source rows still retained at each owner's capture cut, and responses identify this provenance as `retained_source_rows`.

Use the dataset's `/query` endpoint with decimal nanosecond `start_ns` and `end_ns` strings. The range is half open, both bounds align to the configured interval and origin, and the result has a 4,096-row limit. Use a narrower range when a query exceeds its budget. The SQL relation exposes the same summary as typed columns, including `bucket_start` as a UTC timestamp and COUNT as an integer.

```sql
SELECT bucket_start, sample_count
FROM retained_summary(public.sensor_hourly, $1, $2)
ORDER BY bucket_start;
```

A read captures the complete dataset owner vector. Each partition comes from exactly one authority, either a native snapshot or the sealed archive chosen by metadata. AVG merges sum and count across partitions. Closing a summary publishes and verifies each owner's archive before reclaiming native payloads. Once metadata reports `closed`, the summary can serve independently of the source table. The metadata leader or standalone catalog owner schedules archive collection by indexed expiry and preserves logical expiration across clock rollback. Per-dataset expiry and discard seek cursors live in the archive catalog, so dataset count and metadata restarts cannot reset progress past dependency holds. After verifying the permanent discard completion fence, the authority publishes a revision-fenced collection receipt under metadata decoder version 90, retires the owner journal, and removes archive scheduling work while retaining the public tombstone.

Open `/subscriptions` with the same aligned range or a `window_ns` width. The first response contains a snapshot and an opaque cursor. Send that cursor to `/subscriptions/poll` for committed changes and use `/subscriptions/cancel` to release the session. Updates are keyed by bucket and dimensions. The serving node retains the last committed reply for retries. A cursor that outlives the serving session or its native replay returns `reset_required`. Open a new snapshot in that case. Moving windows read entering buckets even without a source write, and expiration produces removals. Subscription sessions expire after two minutes of inactivity.
