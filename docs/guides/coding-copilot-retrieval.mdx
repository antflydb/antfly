## The Pattern

A coding copilot edits code based on what it retrieved. There is no human checkpoint between retrieval and the edit, and the copilot can't know what it failed to retrieve: if the function that already solves the problem never reaches the context, the copilot reinvents it, badly, and the failure looks like bad model output.

Code retrieval has a particular shape. Sometimes the query is exact (`parseConfig`, an error string, a flag name), and keyword matching wins. Sometimes it's intent ("where are configuration defaults applied?"), and only semantic search finds it. A copilot needs both at once, which is what hybrid retrieval is for.

## 1. Index the Repo

Create a table with a semantic index over file contents. Code benefits from smaller chunks than prose:

```bash
curl -X POST http://localhost:8080/db/v1/tables/repo \
  -H "Content-Type: application/json" \
  -d '{
    "indexes": {
      "code": {
        "type": "embeddings",
        "template": "{{path}} {{body}}",
        "embedder": {
          "provider": "antfly",
          "model": "BAAI/bge-small-en-v1.5"
        },
        "chunker": {
          "provider": "antfly",
          "text": {
            "target_tokens": 150,
            "overlap_tokens": 20
          }
        }
      }
    }
  }'
```

Then insert files, one document per file, with the path as the key:

```bash
curl -X POST http://localhost:8080/db/v1/tables/repo/batch \
  -H "Content-Type: application/json" \
  -d '{
    "inserts": {
      "internal/config/defaults.go": {
        "path": "internal/config/defaults.go",
        "body": "package config\n\n// applyDefaults fills unset fields...\nfunc applyDefaults(c *Config) {...}"
      },
      "internal/config/parse.go": {
        "path": "internal/config/parse.go",
        "body": "package config\n\nfunc parseConfig(raw []byte) (*Config, error) {...}"
      }
    }
  }'
```

In a real pipeline, walk the repo and batch files a few hundred at a time. Re-insert a file on change; the index updates in place.

## 2. Query Both Ways at Once

A hybrid query runs BM25 and vector search in parallel and fuses the results. Exact symbols come from the keyword side, intent matches from the semantic side:

```bash
antfly query --table repo \
  --full-text-search 'body:parseConfig' \
  --semantic-search "where configuration defaults are applied" \
  --indexes "code" \
  --fields "path,body" \
  --limit 30
```

The same query over REST:

```bash
curl -X POST http://localhost:8080/db/v1/query \
  -H "Content-Type: application/json" \
  -d '{
    "table": "repo",
    "full_text_search": {"query": "body:parseConfig"},
    "semantic_search": "where configuration defaults are applied",
    "indexes": ["code"],
    "fields": ["path", "body"],
    "limit": 30
  }'
```

<Callout type="tip">
Build the keyword side from the literal tokens in the user's request (identifiers, error strings, file names) and the semantic side from the task description. They catch different misses.
</Callout>

## 3. Rerank Against the Task

Fusion gets the right candidates into the pool; a cross-encoder reranker orders them by what the copilot is actually trying to do. Rerank against the task description, not the raw keyword:

```bash
antfly query --table repo \
  --full-text-search 'body:parseConfig' \
  --semantic-search "where configuration defaults are applied" \
  --indexes "code" \
  --fields "path,body" \
  --limit 30 \
  --reranker '{
    "provider": "antfly",
    "model": "mixedbread-ai/mxbai-rerank-base-v1",
    "field": "body"
  }' \
  --pruner '{"min_score_ratio": 0.5}'
```

## 4. Fit the Context Budget

A copilot's context window is a budget, and retrieval decides how it gets spent. The retrieval agent endpoint handles the budgeting for you: it assembles reranked, pruned results up to a token limit, so the most relevant code is what makes the cut:

```bash
curl -X POST http://localhost:8080/db/v1/agents/retrieval \
  -H "Content-Type: application/json" \
  -d '{
    "query": "where configuration defaults are applied",
    "queries": [{
      "table": "repo",
      "full_text_search": {"query": "body:parseConfig"},
      "semantic_search": "where configuration defaults are applied",
      "indexes": ["code"],
      "fields": ["path", "body"],
      "limit": 30,
      "reranker": {
        "provider": "antfly",
        "model": "mixedbread-ai/mxbai-rerank-base-v1",
        "field": "body"
      },
      "pruner": {"min_score_ratio": 0.5}
    }],
    "max_context_tokens": 2048
  }'
```

Without a `steps.generation` block, the agent returns the assembled context and sources instead of an answer: exactly what you feed your copilot's model. More context is not the goal; a bigger haystack is not a sharper needle. The goal is that the function the copilot needs is in the window, and the noise is not.
