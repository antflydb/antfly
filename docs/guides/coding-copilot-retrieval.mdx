By the end of this guide, your copilot asks Antfly for context and gets back the files that matter, whether it asked by symbol name (`parseConfig`) or by intent ("where are configuration defaults applied?"), already trimmed to fit its context window. You need Antfly running in standalone mode, which the [Quickstart](/docs/guides/quickstart) leaves you with:

```bash
curl -s http://localhost:8080/db/v1/status | head -c 200
```

Here is the call your copilot will make by the end:

```bash
curl -X POST http://localhost:8080/db/v1/agents/retrieval \
  -H "Content-Type: application/json" \
  -d '{
    "query": "where configuration defaults are applied",
    "queries": [{
      "table": "repo",
      "full_text_search": {"query": "body:parseConfig"},
      "semantic_search": "where configuration defaults are applied",
      "indexes": ["code"],
      "fields": ["path", "body"],
      "limit": 30,
      "reranker": {
        "provider": "antfly",
        "model": "mixedbread-ai/mxbai-rerank-base-v1",
        "field": "body"
      },
      "pruner": {"min_score_ratio": 0.5}
    }],
    "max_context_tokens": 2048
  }'
```

```json
{
  "hits": [
    {

        "path": "internal/config/defaults.go",
        "body": "package config\n\n// applyDefaults fills unset fields..."

```

Four steps get you there.

## 1. Index the Repo

One embeddings index over file contents. Code wants smaller chunks than prose, so a function does not get split from its signature:

```bash
curl -X POST http://localhost:8080/db/v1/tables/repo \
  -H "Content-Type: application/json" \
  -d '{
    "indexes": {
      "code": {
        "type": "embeddings",
        "template": "{{path}} {{body}}",
        "embedder": {
          "provider": "antfly",
          "model": "BAAI/bge-small-en-v1.5"
        },
        "chunker": {
          "provider": "antfly",
          "text": {
            "target_tokens": 150,
            "overlap_tokens": 20
          }
        }
      }
    }
  }'
```

Insert one document per file, keyed by path:

```bash
curl -X POST http://localhost:8080/db/v1/tables/repo/batch \
  -H "Content-Type: application/json" \
  -d '{
    "inserts": {
      "internal/config/defaults.go": {
        "path": "internal/config/defaults.go",
        "body": "package config\n\n// applyDefaults fills unset fields...\nfunc applyDefaults(c *Config) {...}"
      },
      "internal/config/parse.go": {
        "path": "internal/config/parse.go",
        "body": "package config\n\nfunc parseConfig(raw []byte) (*Config, error) {...}"
      }
    }
  }'
```

In a real pipeline, walk the tree and batch a few hundred files per request. Re-insert a file when it changes and the index updates in place.

## 2. Query Both Ways at Once

Exact symbols come from the keyword side. Intent comes from the semantic side. One query runs both and fuses the ranked lists:

```bash
antfly query --table repo \
  --full-text-search 'body:parseConfig' \
  --semantic-search "where configuration defaults are applied" \
  --indexes "code" \
  --fields "path,body" \
  --limit 30
```

Build the keyword side from the literal tokens in the copilot's request (identifiers, error strings, file names) and the semantic side from its description of the task. They catch different misses.

## 3. Rerank Against the Task

Fusion gets the right candidates into the pool. A cross-encoder reranker orders them by how well each one serves what the copilot is trying to do, so rerank against the task description rather than the symbol:

```bash
antfly query --table repo \
  --full-text-search 'body:parseConfig' \
  --semantic-search "where configuration defaults are applied" \
  --indexes "code" \
  --fields "path,body" \
  --limit 30 \
  --reranker '{
    "provider": "antfly",
    "model": "mixedbread-ai/mxbai-rerank-base-v1",
    "field": "body"
  }' \
  --pruner '{"min_score_ratio": 0.5}'
```

## 4. Fit the Context Budget

The retrieval agent does the budgeting. Give it the same query plus `max_context_tokens`, and it assembles the reranked, pruned results up to that limit, most relevant first. That is the call at the top of this page. With no `steps.generation` block it returns context and sources, not an answer, which is what your copilot's model wants to be handed.

## Why More Context Is Not the Goal

A copilot can't know what it failed to retrieve. If the function that already solves the problem never reaches its context, it reinvents that function, and the failure looks like a bad model rather than a bad lookup. The fix is not a bigger window. A bigger window filled with near-misses buries the one file that mattered and spends tokens doing it.

The budget is what makes retrieval choosy. `max_context_tokens: 2048` is a good starting point for a copilot that also carries the user's open file; raise it for a model with a large window, lower it when the copilot's own prompt is already long. Watch what gets cut on real tasks. If the right file is being dropped, the pruner is too tight, not the budget.
