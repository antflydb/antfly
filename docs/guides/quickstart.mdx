Load 10,000 Wikipedia articles into a local `.aflite` database and search them by
keyword. Then upload a snapshot to Antfly Cloud and repeat the query there. You
can stop after the local search; it needs no model download or Cloud account.
Semantic search, image search, reranking, and RAG are optional follow-ons.

**Prefer to start hosted?** Follow [Get started with Antfly Cloud Lite](/docs/cloud/getting-started).
It uses the same documents and HTTP requests. Lite is the default Cloud offering;
availability is controlled per organization during rollout.

## Install Antfly

Use [Antfly v0.3.0-rc.3](https://github.com/antflydb/antfly/releases/tag/v0.3.0-rc.3)
for this walkthrough, matching the runtime documented for Cloud snapshot
compatibility. Download the archive for your OS and architecture, verify its
published checksum, and extract the archive. Keep its supporting files beside
the `antfly` binary and add that directory to your `PATH`.

```bash
antfly --version
```

Check that this reports `0.3.0-rc.3`. This is a prerelease; a Homebrew or latest
installation may select a different version. Check file compatibility before
opening the same database with another runtime. See [Downloads](/docs/downloads)
for the other installation options.

## Start a local Lite database

In a new directory, start the HTTP server with Lite storage:

```bash
mkdir antfly-quickstart
cd antfly-quickstart
antfly standalone --storage-engine lite \
  --storage-path "$PWD/quickstart.aflite" \
  --data-dir "$PWD/data" \
  --models-dir "$PWD/models" \
  --ml-dir "$PWD/ml" \
  --secret-store-path "$PWD/secrets.json" \
  --host 127.0.0.1 --port 8080 --fsync true
```

Leave this terminal running. The database lives in `quickstart.aflite`; the other
paths keep this example's server state separate from your existing installations.
The dashboard is at [http://127.0.0.1:8080](http://127.0.0.1:8080).

## Connect and create a table

Open another Bash terminal in the same `antfly-quickstart` directory. Set the
data API endpoint and define a helper for the requests below:

```bash
ANTFLY_ENDPOINT=http://127.0.0.1:8080/db/v1
ANTFLY_API_KEY=''
antfly_request() {
  {
    printf 'header = "Content-Type: application/json"\n'
    if [ -n "$ANTFLY_API_KEY" ]; then
      printf 'header = "Authorization: Bearer %s"\n' "$ANTFLY_API_KEY"
    fi
  } | curl --config - --silent --show-error --fail-with-body --max-time 60 \
    --request POST --data "@$1" "$ANTFLY_ENDPOINT/$2"
}
printf '{}\n' > table.json
antfly_request table.json tables/default
```

This creates a table named `default`. Every table includes a full-text index.
The helper accepts a JSON filename and an API path. It also supports the scoped
API key you will use if you move this database to Cloud.

## Load Wikipedia

Download the sample dataset, then load it into the `default` table:

```bash
curl --fail --location --output wiki-articles.jsonl \
  https://cdn.antfly.io/datasets/wiki-articles-10k-v001.json
ANTFLY_URL="${ANTFLY_ENDPOINT%/db/v1}" antfly load \
  --table default --file wiki-articles.jsonl \
  --id-field title --sync-level full_text
```

The download is about 12 MB: one JSON document per line, with `title`, `body`,
and `url` fields. Some articles also include a thumbnail URL. This step indexes
text only; it does not download images or models.

Wait for the load to complete successfully with 10,000 documents. Titles become
stable document IDs, and `full_text` waits for keyword-search visibility. The
CLI batches the writes for you. Use a fresh database: loading again replaces
articles with the same IDs.

`ANTFLY_URL` is the server base URL; the HTTP helper's `ANTFLY_ENDPOINT` includes
`/db/v1`. The expression above keeps both pointed at the same local server.

## Search by keyword

Find articles that mention Korea and return their titles and source links:

```bash
cat > query.json <<'JSON'
{
  "full_text_search": {"query": "body:\"Korea\""},
  "fields": ["title", "url"],
  "limit": 5
}
JSON
antfly_request query.json tables/default/query
```

Look in `responses[0].hits.hits` for matching articles. Each hit has an `_id`
(the article title) and `_source.title` and `_source.url` fields. Keep the result
so you can compare it with the Cloud copy. Try changing `Korea` to another word
or phrase from the dataset, then rerun the request.

This is full-text search: it matches indexed words, without embeddings or an
inference service. The [SDKs](/docs/sdks) use the same HTTP API.

## Move this database to Cloud

This is optional. Your local database continues working independently.

1. [Sign up for Antfly Cloud](https://platform.antfly.io), verify your email,
   create an organization, and complete billing setup. Review the displayed
   price; a free-year offer is available only when the campaign is enabled and
   your organization is eligible. Claiming it requires a saved card.
2. In your second terminal, prepare a consistent snapshot:

```bash
antfly lite snapshot quickstart.aflite --out upload.aflite
```

3. In Cloud, choose **Bring a Lite database**, select `upload.aflite`, and choose
   **Upload or resume snapshot**. Wait for compatibility verification, then
   **Review and create database**. This creates a new managed database from the
   snapshot; you do not need to create an empty Cloud database first.
4. Wait for **Ready**, create an API key with read/write access restricted to
   this database's `default` table, and copy the instance endpoint. Keep the key
   out of source control and public browser code.
5. In the second terminal, replace `INSTANCE_ID`, read the key without echoing
   it, and repeat the query:

```bash
ANTFLY_ENDPOINT=https://platform.antfly.io/cloud/v1/INSTANCE_ID/db/v1
read -r -s -p 'API key: ' ANTFLY_API_KEY
printf '\n'
antfly_request query.json tables/default/query
```

Expect the same article IDs, titles, and URLs. Do not repeat the table creation
or dataset load: the snapshot already contains all 10,000 articles and their
full-text index. Your HTTP requests stay the same;
the endpoint and authentication change. An application using an embedded Lite
binding needs an HTTP client or adapter to connect to Cloud.

<Callout type="info">
The two copies are independent: later local writes do not sync to Cloud. For a
real application cutover, pause writes before the final snapshot, verify the
managed copy, then switch your application. Keep your original file. A snapshot
includes stored data and artifacts, but external models, credentials, and media
dependencies need separate configuration and compatibility checks.
</Callout>

To take a copy back, follow [Export and serve locally](/docs/cloud/getting-started#take-the-database-back-to-your-laptop).
That path uses the Lite-backed HTTP server to reopen Cloud table namespaces.

## Optional: add semantic search and local AI

[Search Wikipedia with local AI](/docs/guides/wikipedia-search) uses this same
10,000-article dataset to add embeddings, semantic and image search, reranking,
and RAG. That guide sets up a separate local instance with its own model and
memory requirements; you can reuse the downloaded `wiki-articles.jsonl` file.
None of that model setup is required for the keyword search or snapshot above.

Before moving an enriched database to Cloud, qualify its exact models and index
configuration in the destination. The local AI guide's 8 GiB inference budget
is not a managed Lite capacity or model-compatibility guarantee.

## Troubleshooting and cleanup

- **Wrong runtime:** use `antfly --version` and check the extracted binary's
  directory is first on your `PATH`; keep its supporting files beside it.
- **Connection refused:** leave the first terminal running and check the server
  log. If port 8080 is occupied, choose another `--port` and change
  `ANTFLY_ENDPOINT` to match.
- **Table already exists:** skip creation if you are continuing this example.
  Use a new directory for a fresh run; do not overwrite an existing database.
- **Cloud creation unavailable or compatibility rejected:** follow the message
  in Cloud. Availability depends on your organization. Preserve the snapshot;
  do not substitute models or bypass compatibility checks.
- **Cloud database asleep:** use **Resume database**, wait for **Ready**, and
  retry. Queries do not wake it automatically. See [billing and inactivity](/docs/cloud/billing-usage).

Stop the local server with <kbd>Ctrl</kbd>+<kbd>C</kbd>. Your `.aflite` remains on
disk. If you created a Cloud database, revoke temporary keys when finished and
review its billing commitments. Stopping the local server or deleting a local
file does not delete the managed database or stop its billing.
