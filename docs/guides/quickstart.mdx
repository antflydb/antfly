Load 10,000 Wikipedia articles into a local `.aflite` database and search them by
keyword with the Antfly CLI. No model download or Cloud account is required.
After that, you can [move the database to Cloud](#move-this-database-to-cloud) or
continue with the [optional AI steps](#optional-local-ai) on this page.

## Install Antfly

Download [Antfly v0.3.1](https://github.com/antflydb/antfly/releases/tag/v0.3.1)
for your OS and architecture, verify its published checksum, and extract the
archive. Keep its supporting files beside the binary and add that directory to
`PATH`. See [Downloads](/docs/downloads) for installation options.

```bash
antfly --version
```

This walkthrough uses `0.3.1`. Check file compatibility before opening an existing
Lite database with another runtime version.

## Start Antfly

In a new directory, start Antfly with Lite storage:

```bash
mkdir antfly-quickstart
cd antfly-quickstart
antfly standalone --storage-engine lite --storage-path "$PWD/quickstart.aflite"
```

Leave this terminal running. The API and dashboard are at
[http://127.0.0.1:8080](http://127.0.0.1:8080), and fsync is enabled by default.
`--storage-path` selects the database file. Other server state uses `~/.antfly`;
add `--data-dir "$PWD/state"` if you want a separate server-state directory.

## Create a Table

Open a second terminal in the same directory. The CLI defaults to the local
server; clear any Cloud connection settings from an earlier session:

```bash
unset ANTFLY_URL ANTFLY_TOKEN ANTFLY_USERNAME ANTFLY_PASSWORD
unset ANTFLY_DATABASE ANTFLY_NAMESPACE
antfly table create --table wikipedia
```

Every table has a full-text index, `full_text_index_v0`. No embedding index is
needed for the first query. The [SDKs](/docs/reference/sdks) use the same query API.

## Download Sample Data

```bash
curl --fail --location --output wiki-articles.jsonl \
  https://cdn.antfly.io/datasets/wiki-articles-10k-v001.json
```

The download is about 12 MB, with one JSON document per line: `title`, `body`,
and `url`. Of these articles, 2,446 of the 10,000 also have `thumbnail_url`.
The keyword steps do not download images or models.

## Load Data

```bash
antfly load --table wikipedia \
  --file wiki-articles.jsonl \
  --id-field title \
  --sync-level full_text
```

Wait for the load to finish successfully with 10,000 documents. The CLI batches
the writes and waits for keyword-search visibility. Titles become stable IDs;
loading again replaces documents with the same IDs.

## Search

### Full-Text Search

Find articles mentioning Korea:

```bash
antfly query --table wikipedia \
  --full-text-search 'body:"Korea"' \
  --fields "title,url" \
  --limit 5
```

The results include article titles and source links. Add the global option
`antfly --output json query ...` when you need the complete JSON response.
Try another word or phrase, or continue to Cloud or local AI below.

## Move this database to Cloud

Follow [Move a database to Antfly Cloud](/docs/guides/cloud-migration) to take a
consistent `.aflite` snapshot, upload it, and run the same CLI query against the
managed copy. Import creates a new database; it does not require reloading
Wikipedia. Your local copy remains independent.

## Optional local AI

The remaining steps add embeddings, semantic and image search, reranking, and RAG
to the same local table. They are optional and can take 45–90 minutes, mainly for
model downloads and background indexing. Their model and memory requirements are
separate from the managed Cloud Lite package.

If you followed the migration guide, reconnect the CLI to your local server:

```bash
unset ANTFLY_URL ANTFLY_TOKEN
```

For the all-local RAG example, stop the server with <kbd>Ctrl</kbd>+<kbd>C</kbd>,
then restart the same file with an 8 GiB inference budget and a captured log:

```bash
antfly standalone --storage-engine lite --storage-path "$PWD/quickstart.aflite" \
  --inference-host-budget-mb 8192 2>&1 | tee antfly.log
```

If you chose a separate `--data-dir` earlier, use the same path when restarting.
Skip the larger budget if you plan to use a hosted generator. In the second
terminal, continue with the model and index setup.

### Install the text embedding model

```bash
antfly inference pull hf:google/embeddinggemma-2:bf16-safetensors-bundle-v1
antfly inference list
```

EmbeddingGemma2 embeds text, images, audio, and video in the same 768-dimensional
space and runs on CPU, Metal, or CUDA. The running process picks up the new model
on its next model-list or inference request.

### Add text embeddings

Add an index to the table you already loaded:

```bash
antfly index create --table wikipedia \
  --index title_body \
  --type embeddings \
  --template '{{title}} {{body}}' \
  --embedder '{"provider":"antfly","model":"google/embeddinggemma-2:bf16-safetensors-bundle-v1"}' \
  --chunker '{"provider":"antfly","text":{"target_tokens":200,"overlap_tokens":25}}'
```

Antfly backfills the existing articles; do not reload them. Wait until 10% of
source documents have searchable embeddings:

```bash
antfly index wait --table wikipedia \
  --index title_body \
  --until source-covered=10% \
  --timeout 45m
```

Index artifact counts are per chunk, so they can exceed the article count.
Coverage continues growing while you try the following searches.

### Semantic Search

Find articles semantically similar to a natural language query:

```bash
antfly query --table wikipedia \
  --semantic-search "anatomy and physiology" \
  --indexes "title_body" \
  --fields "title,url" \
  --limit 5
```

## Hybrid Search & Reranking

One query can run the keyword and semantic searches together; Antfly fuses the two ranked lists with Reciprocal Rank Fusion. The Qwen3 text reranker then rescores each query-document pair to improve the ordering of those candidates.

Pull the reranker model:

```bash
antfly inference pull hf:ggml-org/Qwen3-Reranker-0.6B-Q8_0-GGUF:gguf:Q8_0 --tasks rerank
```

The first query loads the model, so it can take tens of seconds.

```bash
antfly query --table wikipedia \
  --full-text-search 'body:Einstein' \
  --semantic-search "theory of relativity and physics" \
  --indexes "title_body" \
  --fields "title,url" \
  --limit 10 \
  --reranker '{
      "provider": "antfly",
      "model": "ggml-org/Qwen3-Reranker-0.6B-Q8_0-GGUF:gguf:Q8_0",
      "field": "body"
    }' \
  --pruner '{"min_score_ratio": 0.01}'
```

Reranking changes the order and keeps the count. Pruning changes the count: `min_score_ratio` keeps only results scoring at least that fraction of the top result, and `max_score_gap_percent` stops at the first sharp drop. [Tune Hybrid Search](/docs/guides/hybrid-search) covers both in depth.

## Image Search

EmbeddingGemma2 places text and images in one embedding space, so you can describe a picture in words and get the articles whose thumbnails match.

<Steps>
### Add an image index to your table

Add a second index with the same [EmbeddingGemma2 model](#install-the-text-embedding-model), this time embedding each article's thumbnail:

```bash
antfly index create --table wikipedia \
  --index thumbnail \
  --type embeddings \
  --coverage-policy partial \
  --template "{{#if thumbnail_url}}{{remoteMedia url=thumbnail_url}}{{/if}}" \
  --embedder '{"provider": "antfly", "model": "google/embeddinggemma-2:bf16-safetensors-bundle-v1"}' \
  --distance-metric cosine
```

Articles without thumbnails are skipped. Wait for 250 searchable images:

```bash
antfly index wait --table wikipedia \
  --index thumbnail \
  --until searchable-artifacts=250 \
  --timeout 45m
```

### Search by visual content

Describe what you want to see:

```bash
antfly query --table wikipedia \
  --semantic-search "map of a country" \
  --indexes "thumbnail" \
  --fields "title,url,thumbnail_url" \
  --limit 5
```

Concrete visual descriptions ("red sports car", "mountain landscape") work better than abstract ones. The same pipeline enriches your own documents: PDFs and scans are read with OCR ([LightOnOCR-3](/docs/guides/models/lightonocr3) locally, or a connected provider), and audio is transcribed before indexing. See [Index PDFs and Scanned Documents](/docs/guides/index-documents) and [Index Recorded Calls and Podcasts](/docs/guides/transcription).
</Steps>

## RAG (Retrieval-Augmented Generation)

The retrieval agent plans the query, runs the search, and hands the results to a local language model to write the answer.

<Steps>
### Pull a generation model

```bash
antfly inference pull hf:ggml-org/gemma-4-E4B-it-GGUF:gguf:Q4_0 \
  --tasks generate \
  --projector auto
```

`--projector auto` includes image and audio input; `--projector none` is a smaller, text-only download. To use a hosted model instead, skip to [RAG with alternative providers](#rag-with-alternative-providers).

### Build a query and generate an answer

Give Gemma an intent and a table. The retrieval agent delegates query planning
to the query builder, searches, and answers from the results.

```bash
antfly agents retrieval --table wikipedia \
  --intent "What are the major events in Korean history?" \
  --fields "title,body" \
  --limit 5 \
  --generator '{
    "provider": "antfly",
    "model": "ggml-org/gemma-4-E4B-it-GGUF",
    "max_tokens": 512
  }' \
  --max-internal-iterations 8 \
  --streaming
```

The command streams Server-Sent Events as each step completes and ends with `event: done`. Use `--no-streaming` to get one JSON body with the answer and its sources. To see the query the agent would run without running it, use `antfly agents query-builder` with the same `--table`, `--intent`, and `--generator`.

## Troubleshooting

- **Wrong runtime or command not found:** check `antfly --version` and the extracted
  binary's location on `PATH`. Keep the archive's supporting files beside it.
- **Port conflict:** choose another `--port` and, if needed, `--health-port`.
  Set `ANTFLY_URL` to the matching server base URL in the CLI terminal.
- **Table already exists:** skip creation when continuing this example, or use a
  fresh directory and `.aflite` path. Do not overwrite a database you want to keep.
- **Legacy server state:** use a fresh `--data-dir` and preserve the old directory.
- **Model not found:** run `antfly inference list` and inspect the
  `standalone inference paths` line in `antfly.log`. Confirm that the server and
  CLI use the same model directory.
- **Index wait timed out:** capture `antfly index list --table wikipedia --output json`
  and the recent server log. Counts that keep growing on unchanged data or
  coverage that never advances need investigation.
- **Memory errors:** stop other large local models, use a hosted generator, or
  increase `--inference-host-budget-mb` if your machine has capacity.

Stop the server with <kbd>Ctrl</kbd>+<kbd>C</kbd>. The `.aflite` file remains on disk.
Stopping this local process does not delete a managed Cloud copy or stop its billing.

## Give Your Agent the Antfly Skill

Everything you just did by hand, a coding agent can do for you. The [Antfly skill](https://github.com/antflydb/antfly-skills) carries verified, current knowledge of Antfly's APIs, query shapes, React components, and operations, for Claude Code, Cursor, Codex, and other agent harnesses:

```bash
npx skills add antflydb/antfly-skills
```

From here your agent can create tables, build indexes, and write queries against the instance you just started.
