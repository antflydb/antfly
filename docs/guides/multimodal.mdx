By the end of this guide, "map of a country" returns the articles whose thumbnails are maps, and an image URL returns the pictures that look like it. No captioning step, no vision model in the middle: one embedding model places text and images in the same space, and it runs on Antfly Inference inside your instance. The examples run against the Wikipedia table from the [Quickstart](/docs/guides/quickstart), whose articles carry a `thumbnail_url` field:

```bash
antfly query --table wikipedia --full-text-search 'title:Iceland' --fields title,thumbnail_url --limit 1
```

Here is the query you'll be running by the end:

```bash
antfly query --table wikipedia \
  --semantic-search "map of a country" \
  --indexes "thumbnail" \
  --fields "title,thumbnail_url" \
  --limit 5
```

Four steps get you there.

## 1. Pull the Model

ClipClap is a multimodal embedding model that understands text, images, and audio. Pull it onto Antfly Inference:

```bash
antfly inference pull antflydb/clipclap:gguf:Q4_K
```

If the running instance does not pick it up, restart `antfly standalone`.

## 2. Add an Image Index

The index template fetches each article's thumbnail and hands the bytes to the embedder. Articles without a thumbnail render an empty template and are skipped:

<Tabs defaultValue="cli">
  <TabsList>
    <TabsTrigger value="cli">CLI</TabsTrigger>
    <TabsTrigger value="curl">cURL</TabsTrigger>
  </TabsList>

  <TabsContent value="cli">
```bash
antfly index create --table wikipedia \
  --index thumbnail \
  --type embeddings \
  --coverage-policy partial \
  --template "{{#if thumbnail_url}}{{remoteMedia url=thumbnail_url}}{{/if}}" \
  --embedder '{"provider": "antfly", "model": "antflydb/clipclap"}' \
  --dimension 512
```
  </TabsContent>

  <TabsContent value="curl">
```bash
curl -X POST http://localhost:8080/db/v1/tables/wikipedia/indexes/thumbnail \
  -H "Content-Type: application/json" \
  -d '{
    "type": "embeddings",
    "coverage_policy": "partial",
    "template": "{{#if thumbnail_url}}{{remoteMedia url=thumbnail_url}}{{/if}}",
    "embedder": {
      "provider": "antfly",
      "model": "antflydb/clipclap"
    },
    "dimension": 512,
    "distance_metric": "cosine"
  }'
```
  </TabsContent>
</Tabs>

`{{remoteMedia url=...}}` downloads the image and prepares it as model input. It accepts `http://`, `https://`, `s3://`, and `file://` URLs, refuses private IP ranges, and caps downloads at 100 MB. For images you already hold as data URIs, use `{{media url=...}}` instead.

## 3. Wait for the Backfill

The index embeds every existing article in the background. Wait for it before querying:

```bash
antfly index wait --table wikipedia --index thumbnail --until complete --timeout 20m
```

## 4. Search by Description, or by Image

Describe what you want to see:

```bash
antfly query --table wikipedia \
  --semantic-search "map of a country" \
  --indexes "thumbnail" \
  --fields "title,thumbnail_url" \
  --limit 5
```

Or hand it an image. `embedding_template` tells Antfly how to turn the `semantic_search` value into an embedding, and `this` is that value:

```bash
curl -X POST http://localhost:8080/db/v1/query \
  -H "Content-Type: application/json" \
  -d '{
    "table": "wikipedia",
    "semantic_search": "https://upload.wikimedia.org/wikipedia/commons/thumb/2/2e/Iceland_location_map.svg/500px-Iceland_location_map.svg.png",
    "embedding_template": "{{remoteMedia url=this}}",
    "indexes": ["thumbnail"],
    "fields": ["title", "thumbnail_url"],
    "limit": 5
  }'
```

A base64 data URI works the same way with `{{media url=this}}`. Mix text and image in one query by writing both into the template: `"Find pages like this: {{remoteMedia url=this}}"`.

## Why One Model Sees Both

The older way to search images was to caption them first: run a vision model over every picture, store the caption, embed the caption. Search then matched your words against the captioner's words, and the captioner decided in advance which details were worth a sentence.

A multimodal embedder skips the sentence. Text and images land in one vector space, so "map of a country" and a picture of a map sit near each other with no description in between, and a query image compares directly against indexed images. That is also why the image index is a separate index rather than a field folded into the text index: the two spaces are different, and a query names which one it is asking. When you want text and picture weighed together, put both in one template (`{{title}} {{remoteMedia url=thumbnail_url}}`) and the model embeds the pair as one item.

`coverage_policy: partial` is the other decision. The default, `strict`, requires one embedding per source document. Image fields are usually optional, so `partial` counts a document whose template rendered nothing as a deliberate skip, and the index still reaches `complete`. `best_effort` goes one step further and treats outright failures (a dead URL, an oversized file) as complete too, while reporting the index unhealthy.
