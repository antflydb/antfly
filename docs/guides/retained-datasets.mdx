Retained datasets give prepared record snapshots and aggregate-state segments an independent identity, schema, coverage, and lifetime. Local residence is separate from logical retention. The same immutable segment can move from local storage to an object-backed location without becoming an additional query input.

The administrative storage API accepts already prepared segments. Native retained summaries additionally capture source writes and existing rows, run automatic maintenance, serve through HTTP and `retained_summary(...)` SQL, and support bounded HTTP subscriptions. Single-writer standalone local and Lite use the same verified owner and archive handoff protocol. See [the lifecycle design](https://github.com/antflydb/antfly/blob/main/docs/design/retained-dataset-lifecycle.md).

## Activation and cancellation

Distributed native owners require administrator-approved physical store-root signing identities. Generate a proof on each data store with `antfly internal store-root proof --replica-root-dir <path> --metadata-incarnation <cluster-incarnation> --node-id <node> --store-id <store>`, then submit it once to `POST /store-roots/enroll` as a cluster administrator. Enroll replacement physical roots before they serve retained owners. Ordinary node registration does not grant this authority. Until enrollment, activation remains pending and owner diagnostics report `StoreRootEnrollmentChanged`; enrolling the exact root lets maintenance resume automatically. Standalone local and Lite enroll their own single-writer binding during startup.

Creating a summary starts asynchronous activation over retained source rows. Dimensions and measures share one output-column namespace; their names must be distinct and cannot use generated column names. Existing rows must have valid timestamps. The source remains protected while activation or closure is in progress.

To cancel an activating summary, POST its current `expected_revision` and `cancel_activation: true` to `/databases/{database}/namespaces/{namespace}/datasets/{dataset}/close`. Cancellation enters `retiring`, discards partial summary state, and stops further registration. Owners must durably revoke capture and reclaim their state before the source dependency is released. This also recovers activation blocked by invalid historical rows. Closing an active summary instead preserves its summaries through verified archive handoff.

Maintenance drains fair indexed batches with a 64-owner and 100 ms turn budget. Within a visit, an owner drains up to 32 native pages or 25 ms, stopping for verified acknowledgement on each lifecycle transition. A full sweep sleeps only when no owner exhausts its work budget. Each owner uses a separate working arena, and a failed native command does not prevent other owners from progressing. Archive readers retry catalog conflicts with bounded jittered backoff. Failed archive handoffs use revision-scoped exponential backoff with jitter, starting near one second and capped at 30 seconds; healthy owners continue independently. An unsuccessful export does not keep the maintenance sweep busy. Native and archived reads durably admit retention clocks at bucket expiry boundaries, so wall-clock rollback cannot revive history that a read already rejected as expired. Native read admission is replicated and does not change the source sequence or emit subscription events. Native subscription polls admit and return that same durable clock before filtering rows or advancing a moving window.

Public summary field names identify literal top-level source properties, including names containing dots. Creation validates timestamp, dimension, and measure references against every declared document schema and persists the extraction program with the source schema identity. Missing scalar properties contribute SQL NULL; `COUNT(*)` counts rows, while `COUNT` of a JSON column counts a present JSON null and excludes a missing or SQL-null column.

## Serving and discarding summaries

The query endpoint accepts `max_rows` (1–4096), an optional exact `dimensions` tuple in definition order, and an opaque `after` key. Follow the returned `next` key with the same range and filter until it is null; an empty page can still have a continuation. Ordering is by bucket time and dimension hash. Archive pages stop at file or byte boundaries with a continuation; an individual file must fit the page budget. Each page admits a fresh authority cut, so active summaries can change between pages. Closed archives provide stable contents until retention expires them.

SQL finalizes only the retained measures required by projections, predicates, and ordering. An overflowing SUM does not prevent reading an independent COUNT or finite AVG. SQL observes that overflow only when an expression actually demands the cell: filtered rows, skipped rows, and unselected CASE/COALESCE branches preserve lazy evaluation. Zero-row limits validate binding and invocation parameters without opening retained data cursors. Certified finite prefixes continue across short or empty archive coverage pages within one working-memory, input-row, and deadline budget; they do not fall back to reading the entire range.

SQL pushes complete dimension equality predicates into native seeks and archive coverage seeks across the requested range. A plain unordered `LIMIT` also receives an exact prefix certificate when the planner proves there are no residual filters, cardinality observers, ordering, or fallible projections. Advisory row goals alone never truncate a scan. SQL consumes bounded archive pages internally, emits matching tuple rows across each verified file span before planning again, and enforces whole-query admission limits of 128K input rows, 32 MiB of assembled row data and a shared 32 MiB allocation ceiling for reduction and partition reads, 64 MiB of archive file reads per partition, and 8192 archive planning steps; exceeding admission returns an explicit error. Use the paginated endpoint for larger exports. Compound SQL reads certify native owner observations around ordinary statement snapshot capture. Source sequence, replay position, root incarnation, and retention boundaries must agree before any cursor is exposed. Read-only capture retries are bounded; unresolved concurrent changes return retryable SQLSTATE `40001` instead of mixed values. Retained reads in explicit transactions, receipt-bound snapshots, or staged-write overlays remain unsupported.

POST `{ "expected_revision": 1, "discard": true }` to the close endpoint to permanently abandon a summary in any phase, including a close blocked by unavailable archive storage. Discard enters the durable `retiring` tombstone. `source_released` becomes true only after verified native revocation and cleanup. Source release does not require archive availability. Archive cleanup resumes independently when storage returns, respects admitted readers and downstream holds, and fences stale publishers against resurrection. Discard cannot be undone and does not preserve summary history. A close that preserves history exports at its frozen source cut even when later reads expire its initial coverage. Before publishing archive authority, the owner freezes native retention admission and transfers its watermark; revocation compares the transferred clock. Reads requiring a newer native retention boundary retry during that transition.

Subscription retries return the exact committed frame only while its original dataset identity remains admitted for serving. Every retry checks current metadata; discard revokes cached frames too, and reusing a logical name cannot resume a subscription from the previous dataset.

Native scan work limits are permanent admission failures: HTTP returns 413 and SQL returns `54000`, including when a remote owner performs the scan. Narrow the time range or dimension filter before retrying. Numeric and timestamp overflows retain their permanent domain errors across owner RPCs.

Archive maintenance runs independently of native maintenance and visits up to 32 resources/segments or 100 ms per turn. Busy sweeps become eligible after 10 ms and run on the next supervisor tick; idle sweeps back off for one second. Expiry and discard cursors persist in each archive catalog, so restarts and dataset count cannot reset progress past held segments. Collection compacts already-collected coverage prefixes in bounded batches. Once the archive verifies physical collection, metadata publishes its receipt, retires the owner journal, and removes the dataset from maintenance scheduling while keeping its permanent discard tombstone.

## Administrative operator

Run one bounded operation using a JSON request:

```bash
antfly storage dataset --request request.json
```

The operator opens the catalog and segment locations directly. It requires administrative access to those stores. Use provider credentials through the existing environment/credential configuration; request URIs must not contain credentials. Dataset metadata persists opaque location identities and binding fingerprints, not URIs or secrets.

Catalog and location URIs use the existing `file://`, `s3://`, and `gs://` adapters. Use separate prefixes for catalog metadata and segment contents. Reuse the exact URI spelling for a previously bound location ID: rebinding an ID to a different physical store is rejected.

Every request includes `format: 1`, `catalog_uri`, `dataset` (32 bytes encoded as a JSON integer array), and `action`. Object IDs and digests use the same 32-byte representation. Event-time bounds and bucket origins use decimal strings containing signed nanoseconds. Durations and source sequences also use decimal strings, preserving every u64 value across JavaScript hosts. Generation, incarnation, and placement counters are bounded to JavaScript-safe integers.

| Action | Additional fields | Result |
|---|---|---|
| `create` | `definition` | Create a stable dataset with its initial immutable definition |
| `evolve` | `expected_generation`, `definition` | Publish the next definition while preserving older schemas |
| `status` | Optional `segment_id` | Definition or segment metadata |
| `list` | Optional `after`, `limit` (maximum 128) | Bounded metadata rows; use the last returned key as `after` |
| `publish` | `segment`, `source`, `input` | Verify and publish one complete immutable segment from a file |
| `plan` | `generation`, `partition`, `incarnation`, `range`, optional `limit` | Resolve contiguous exact coverage using ordered range seeks |
| `migrate` | `segment_id`, `expected_revision`, `source`, `destination` | Copy/verify a finalized local segment and publish remote placement |
| `read` | `segment_id`, `source`, `output` | Acquire a bounded reader pin, verify bytes, write the output file |
| `restore` | `segment_id`, `expected_revision`, `source`, `destination` | Restore an archive into local placement without deleting the archive |
| `reclaim_local` | `segment_id`, `source` | Advance reader-safe local eviction; repeat until `complete: true` |
| `reclaim_upload` | `source` | Fence and reclaim one abandoned upload; repeat while `complete: true` reports cleanup or index-upgrade progress |
| `hold` / `release_hold` | `segment_id`, `dependency` | Register/release an exact downstream consumer-generation hold |
| `retire` | `segment_id`, `expected_revision` | Fence new readers after logical expiration, subject to holds/readers |
| `compact` | `segment_id` | Replace a fully collected oldest tombstone with the durable partition retirement floor |
| `collect` | `segment_id`, `source` | Reclaim one retired physical payload and record completion |

A location binding is `{ "id": [...], "uri": "file:///path/prefix", "access": "local" }`. Access is `local`, `queryable`, or `restore_required`. At this layer `queryable` means directly readable by a host with an admitted decoder; it does not create a SQL table. An archive marked `restore_required` rejects new reader pins until restored.

A dependency is `{ "id": [...], "consumer": [...], "consumer_generation": 1 }`. Holds have no automatic deadline. Only release a hold when that consumer's durable requirement is satisfied. A stale release cannot remove a replacement consumer-generation hold.

## Preparing a definition and segment

A definition contains:

- `id`, nonzero `generation`, and `kind` (`records` or `summary`).
- `schema_json`, a self-contained JSON object, and `schema`, its SHA-256 digest.
- `authorization`, the host's dataset authorization-policy identity. The storage operator is administrative; it does not execute that policy on behalf of an untrusted user.
- `retention_ns`, the logical lifetime after a segment's event-range end.
- `local_residence_ns`, a target for a future placement scheduler, no longer than logical retention.
- For summaries, `summary`: source dataset identity, `source_filter_json` (default match-all), timestamp, dimensions, `bucket_semantic_version: 1`, `timezone: "UTC"`, fixed `interval_ns`, decimal `origin_ns`, `mutable_for_ns`, and named measures (`count`, `sum`, `avg`, `min`, `max`).

A segment contains `id`, `dataset`, `definition_generation`, `schema`, `state_encoding`, `coverage`, `source`, `finalized`, `checksum`, `byte_len`, and the initial `location`/`access`. `coverage` is a half-open `{ "start_ns": "...", "end_ns": "..." }` range. `source` contains a `partition` identity, nonzero `incarnation`, and applied `sequence`.

The producer must establish the source snapshot/replay boundary and correctness of the supplied contents. Aggregate producers preserve merge states, including AVG sum and count, rather than finalized averages. Declaring a segment finalized is not a substitute for fencing subsequent source corrections.

Contents are limited to 16 MiB per segment. Split larger outputs into disjoint source-partition/time extents. Metadata rows are limited to 32 KiB. The schema must be a valid bounded JSON object, with at most 16 KiB of source bytes and bounded nesting.

## Migration and retention behavior

Migration publishes remote placement only after full source/destination SHA-256 verification. Local reclamation is separate and waits for older readers. A failed operation can be retried from status; migration retries must use the currently reported placement revision. New uploads are durably inventoried before writing. Automatic archive maintenance reclaims abandoned payloads after fencing publication; administrative catalogs can run `reclaim_upload`. Cleanup uses location-specific inventory and expiry indexes, so an unavailable storage location cannot block another location. Older journals upgrade those indexes in bounded metadata-only steps; global inventory remains authoritative for discard completion. Cleanup retains a zero-byte object fence to reject delayed conditional uploads. Preserve these fences in provider lifecycle policies.

A retained archive survives restore. Permanent expiration must collect every recorded physical copy. Completed collection keeps a tombstone so an old publication retry cannot resurrect deleted history.

Logical expiration blocks new reads even when a downstream hold protects the physical bytes. A read admitted before expiration has only its original bounded lease. Clock rollback cannot extend its authority. Missing coverage, an unavailable resolution, an expired lease, a restore requirement, and a physical binding conflict are explicit errors.

The host API is exported as `serverless.datasets`. It provides typed catalog operations, bounded range planning, reader leases, and a distinct `requireSourceReclamation` proof. Hosts must check current authorization, decoder versions, source topology, and downstream retention dependencies before using these primitives in automatic table workflows.

### Maintenance diagnostics and catch-up

GET a dataset with `max_owners` (1–64, default 16) and optional decimal `after_group` to page through `progress.owners`; use `progress.next_group` for the next page. Status includes registration counters, native readiness, replay bounds, retention clock, last maintenance error/attempt, and archive export frontier. RPC failures appear separately as `status_error`. Diagnostics share a two-second best-effort budget; an unavailable owner or archive does not hide lifecycle metadata. These diagnostics do not grant read or deletion authority.

Subscription frames may include `resynchronized: true` when replay is unavailable or behind the current head. The server reads a fresh bounded owner snapshot and emits the resulting changes. Intermediate source changes can be coalesced. A moving window also resynchronizes the full visible owner partition if its entering-range snapshot is newer than replay or admits a later expiry boundary; overlapping and entering buckets always use one owner cut. This does not provide an atomic cut across different owners. Changed producer identity still requires a reset.

SUM and AVG now preserve exact binary64 contribution sums across corrections and archive merges, rounding only the served value. Existing nonempty generations written with legacy floating state must be rebuilt into a fresh generation before corrections; their archives remain readable.

Subscription cursors authenticate the issuing API node, including metadata-only nodes in split metadata/data deployments. Poll and cancel can use any cluster API endpoint; ingress verifies the cursor and forwards to the issuer with the original credentials, cancellation, and bounded timeout. Missing issuers or lost sessions require a fresh snapshot; transient transport failures preserve the cursor for retry. State stays local and bounded rather than becoming a durable replication slot.

JSON query and subscription reads report numeric overflow as HTTP 422 with `code: retained_series_numeric_overflow` and `retryable: false`; SQL uses SQLSTATE `22003`. Finite input values can still overflow the served SUM even when the exact contribution state remains valid.

Retained JSON/SQL partition reads charge archive catalog navigation, downloaded objects, and decoding against their shared 32 MiB allocation ceiling. Subscription open/poll processing has its own shared 32 MiB working-memory ceiling covering capture, replay, reduction, and serialization, in addition to persisted-state and reply limits. Temporary archive and native partition buffers are reclaimed between captures; sparse or empty results still pay for their input work. Exceeding admission returns HTTP 413 before committing a subscription successor, leaving the prior cursor available for retry.

Private native owner reads also enforce a 32 MiB live allocation ceiling across binding state, validation scratch, page assembly, and serialization. Validation scratch is released before serving, sparse dimension seeks reuse fixed-size keys, and cancellation and deadlines are checked during scans and between serialized rows, including while waiting for read admission. Temporary wire pages are reclaimed after copying owned rows, and the outgoing reply copy must fit the remaining admission budget.

SUM, AVG, MIN, and MAX currently require binary64 (`DOUBLE PRECISION`, or a document `number`) source fields. Exact `INTEGER` and `NUMERIC` measure fields are rejected at creation rather than implicitly rounded. COUNT accepts these domains and retains an exact integer count. Integer dimensions remain exact, including values above 2^53. Exact integer/decimal measures require a new versioned aggregate-state and result-type contract; casting a source value changes the promised numeric domain.

Retained snapshot validation, native status, and replay processing release the source apply lock immediately after snapshot capture. Snapshot opening validates progress and range admission without visiting buckets; the first page scans them once. Their scans, decoding, and serialization honor cancellation and deadlines. Public JSON and SQL retained reads share their live allocation admission through partition reads and output projection; JSON serialization and the outgoing copy must fit the same ceiling. Measure-only SQL scans skip dimension decoding.
